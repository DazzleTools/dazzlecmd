## HV.1 -- The prompt renders correctly at a REAL interactive terminal

Validates: moving the prompt to stderr (with an explicit flush) did not break the interactive experience -- a buffering mistake would show a blank line waiting for input with the question appearing only *after* you answer.

- [ ] **Steps:** in each shell you use day-to-day (cmd.exe, PowerShell, git-bash), run a `#` ref whose repo-part is ambiguous in your cache with no exact match (verify ambiguity first with `dz github -n repo <prefix>`; on this machine `dazzle-clau` worked on 2026-08-10):
  ```
  dz github -n dazzle-clau#1
  ```
- [ ] **Expected:** the candidate list AND the `Which repo? [1-N]:` prompt are visible BEFORE the cursor waits; typing a number selects that candidate; the URL prints after.
- [ ] **Must NOT happen:** a silent hang with no visible question (stderr buffering), or the prompt appearing interleaved into the URL line.

## HV.2 -- Piped capture is clean in YOUR shells

Validates: the actual scripting contract the fix exists for.

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  echo 1 | dz github -n dazzle-clau#1 2>nul
  ```
  **PowerShell**:
  ```powershell
  echo 1 | dz github -n dazzle-clau#1 2>$null
  ```
  **POSIX**:
  ```bash
  echo 1 | dz github -n dazzle-clau#1 2>/dev/null
  ```
- [ ] **Expected:** output is exactly one URL line. No `Which repo?` fragment glued to it.

## HV.3 -- One real browser launch (the arc's standing MANUAL item)

Validates: the non-`-n` path end to end. Every automated and agent check across v0.12.18 AND v0.12.19 used `-n`; no human or agent has ever opened an actual browser through the `#` grammar.

- [ ] **Steps:** `dz github dazzlecmd#112`
- [ ] **Expected:** your default browser opens issue 112 of dazzlecmd. Terminal shows the resolution announcement on stderr.
