# Human Test Checklist: Per-Repo `--fix` and a `--scope` That Filters

**Target version:** 0.12.14-alpha
**Ships with commit:** TBD (fixes #114 and #115)
**Companion automated tests:** 14 new in `dazzle-update/tests/test_query.py` (10 for scoped `--fix`, 4 for the scope lens); tool suite 255; full repo suite 2381.

## What this is

Two changes to how the report is scoped, both from issues filed after using the tool on a second machine:

- **#114** — `--fix` now composes with a repo query, so a single repo can be fixed on its own. Guarded by a uniqueness gate: a name matching several actionable repos refuses and lists them rather than acting broadly.
- **#115** — `--scope` now actually filters the report. It previously narrowed only the GitHub enumeration, leaving every on-disk repo rendered, and — worse — corrupted ownership, so under `--scope DazzleLib` your own `DazzleTools/dazzlecmd` read "not ours" and would have been refused by `--fix`.

`--fix` writes to real repositories. Every step below that could write is marked, and the safe form is given first.

## Prerequisites

1. dazzlecmd 0.12.14 installed editable; `gh` authenticated; a prior scan so the cache exists.
2. **Pick a throwaway or well-understood repo for any step that writes.** Steps marked SAFE never write.
3. Know your own numbers first — run `dz dazzle-update --cached` once and note the totals, so "did the lens change anything" is answerable.

## High-Value Verification (~5 minutes)

### HV.1 — `--scope` filters, and says what it hid — SAFE

- [ ] **Steps:** `dz dazzle-update --cached --scope DazzleLib`
- [ ] **Expected:** only `DazzleLib/*` rows. A `SCOPE` line names the namespace and counts what it hid. Before this fix the same command rendered 32 out-of-scope rows.
- [ ] **Why this matters:** the flag's help text promised filtering that did not happen.

### HV.2 — Scoping does not change what you own — SAFE

- [ ] **Steps:** `dz dazzle-update --cached --scope DazzleLib` and look for the string `not ours` anywhere.
- [ ] **Expected:** absent. Then `dz dazzle-update --cached --scope DazzleTools` and confirm your own repos are not labelled "not ours" there either.
- [ ] **Why this matters:** the old code derived ownership from the scoped list, so a lens silently disowned repos — and `--fix` refuses repos it thinks you do not own.

### HV.3 — Unknown scope warns instead of returning an empty machine — SAFE

- [ ] **Steps:** `dz dazzle-update --cached --scope NoSuchOrg`
- [ ] **Expected:** a WARNING naming the typo and listing known namespaces. Not a silent empty report.
- [ ] **Why this matters:** an empty report reads as "everything is fine".

### HV.4 — Single-repo `--fix` plans only that repo — SAFE (dry run)

- [ ] **Steps:** pick a repo with a finding, then `dz dazzle-update <name> --fix --dry-run`
- [ ] **Expected:** the card, then `APPLYING FIXES to <Owner/Repo> (dry run)`, then the planned actions for that repo alone. Anything `--fix` never touches is listed separately under `NOT ACTED ON`.
- [ ] **Why this matters:** the feature. Confirm no other repo appears in the plan.

### HV.5 — An ambiguous name refuses rather than fanning out — SAFE

- [ ] **Steps:** `dz dazzle-update git-repokit --fix --dry-run` (or any name matching several repos)
- [ ] **Expected:** `--fix needs ONE repo; this matched 3:` followed by the list, nothing applied, exit 2. Then qualify it (`DazzleTools/git-repokit`) and confirm it proceeds.
- [ ] **Why this matters:** `--fix "dazzle*" --yes` would otherwise touch dozens of repos; per-action confirmation at that scale is fatigue, not safety.

## Section 1: The uniqueness gate in detail (~5 min) — SAFE

### 1.1 Uncloned matches do not create ambiguity
- [ ] Query a name that matches one local repo plus repos you have not cloned. Expected: it proceeds on the real one rather than refusing.

### 1.2 A match with nothing to act on
- [ ] `dz dazzle-update <a-not-cloned-repo> --fix --dry-run`. Expected: `nothing to act on — the match is not cloned here, or every checkout is excluded`, exit 2.

### 1.3 No match says only that
- [ ] `dz dazzle-update definitely-no-such-repo --fix --dry-run`. Expected: `no repo matches` and the matching-surfaces hint — and **not** a claim about clone status for a repo that was never found.

## Section 2: Flag composition (~5 min)

### 2.1 Both orders — SAFE
- [ ] `--fix <name> --dry-run` and `<name> --fix --dry-run` behave identically.

### 2.2 `--no-fetch` refuses the pull half — SAFE
- [ ] On a repo that is behind: `<name> --fix --dry-run --no-fetch`. Expected: `skipping pulls: --no-fetch means behind-counts were not verified this run`. A stale-install finding on the same repo should still be planned.

### 2.3 JSON still refuses — SAFE
- [ ] `<name> --fix --json`. Expected: refusal naming `--dry-run`; exit 2; nothing applied.

### 2.4 **WRITES** — apply for real
- [ ] On a repo you are willing to change: `<name> --fix`. Expected: per-action confirmation (`y/N/a/q/?`), a bare Enter declines, `?` explains. Verify with `git status` / `pip show` afterward that exactly the confirmed action happened.
- [ ] Re-run the same command. Expected: the finding is gone and there is nothing to do — the read-fix-verify loop closes.

## Section 3: Interactions (~3 min) — SAFE

- [ ] `--scope` composes with `--only`: `--cached --scope DazzleLib --only dirty` shows only dirty rows within that namespace.
- [ ] `--scope` composes with `--only-set`: both lens lines appear and both counts are stated.
- [ ] `--scope` on the cached path behaves as on a fresh scan (it was ignored entirely on `--cached` before this fix).

## What the automated tests DO cover

Uniqueness gate (multi-match refusal, uncloned/excluded exclusion, install-only records), scoping of the findings passed to `apply_fixes`, `--no-fetch` pull suppression, the JSON refusal, the no-match-vs-nothing-actionable distinction, and the scope lens (owner filtering, case-insensitivity, hidden counting, remote-less repos).

## What the automated tests DON'T cover

- A real write against a real repository — every automated test fakes the runner
- The interactive confirmation prompt on a real TTY (`y/N/a/q/?`, bare Enter, Ctrl-C)
- Whether the `SCOPE` and `APPLYING FIXES` lines read clearly in a real terminal at real width
- Whether the multi-match refusal lists enough to actually disambiguate from
- `gh` unauthenticated: whether `--scope` still behaves sensibly with no namespace list

## Reporting issues found

Include the exact command, the full output, and `git status --porcelain` for any repo that was written to.
