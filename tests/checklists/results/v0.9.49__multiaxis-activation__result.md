## Section 2: Visibility Surface (Slice-1 Spot Checks)

### 2.1 -- `dz kit visibility status` on constitutional tool [PASS with annotation]

**Command:** `dz kit visibility status core:safedel`

**Initial stdout:**
```
core:safedel
  presence: visible
  less visible -> dz kit visibility silence core:safedel
  more visible -> (already fully visible)
```

**Clarification note (REVIEW):** The checklist states "the C3-aware navigator still refuses to suggest shadowing a constitutional tool (the 'less visible' line notes shadow is refused)." At `visible` state, the navigator correctly suggests `silence` (not shadow) -- this is expected because `silence` IS a valid less-visible step. The C3 "shadow refused" message only appears when the tool is already at `hidden` state and the user would need `shadow` to go further. This was verified:

After manually silencing and hiding `core:safedel`, the status at `hidden` level showed:
```
core:safedel
  presence: hidden
  less visible -> (none: core:safedel is constitutional -- 'shadow' refused by C3; hidden is the max veil)
  more visible -> dz kit visibility unhide core:safedel
```

The C3 protection message appears correctly at the boundary. The checklist's expected wording matches exactly. The `visible -> silence` suggestion for the initial state is also correct -- silence is the next valid step down the axis.

**Assessment:** Behavior is correct. The checklist expectation was for the C3 message, which appears at the right moment (when at hidden, one step from shadow). PASS -- no regression, no "PRODUCT space refuses cross-axis nav" error anywhere.

Constitutional tool (`core:safedel`) was restored to `visible` after testing: `dz kit visibility unhide core:safedel` -> `Restored: core:safedel (no longer hidden)`.
