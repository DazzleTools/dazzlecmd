## Section 3.3 — help_lib detail Continuum coordinate query

**REVIEW — checklist command incorrect; implementation PASS**

The checklist's Step command:
```python
items=[('a',D.rank('minimal')),('b',D.rank('standard')),('c',D.rank('full'))];
print('std', items_for_rank(items, D.rank('standard')));
print('min_rank', min_detail_rank([D.rank('full'), D.rank('minimal')]))
```
raises `AttributeError: 'tuple' object has no attribute 'contexts'`.

**Root cause (checklist bug, not source bug):** `items_for_rank` expects objects exposing a `.contexts` iterable (documented: "e.g. help_lib `HelpContent`"), not `(name, rank)` tuples. Likewise, `min_detail_rank` takes `Iterable[str]` of context name strings (e.g. `['full', 'minimal']`), not a list of integer ranks. The checklist test command passes incorrect argument types.

**Implementation verified correct** with proper invocation matching `test_help_detail.py` patterns:

```python
from dazzlecmd._vendor.help_lib.detail import items_for_rank, min_detail_rank, DETAIL_CONTINUUM as D
from dazzlecmd._vendor.help_lib.core import HelpContent

def _item(item_id, contexts):
    return HelpContent(id=item_id, command='c', description='d', contexts=set(contexts))

items = [_item('a', {'minimal'}), _item('b', {'standard'}), _item('c', {'full'})]
std_items = items_for_rank(items, D.rank('standard'))
print('std', [it.id for it in std_items])   # -> ['a', 'b']
min_rank_result = min_detail_rank(['full', 'minimal'])
print('min_rank', min_rank_result)           # -> -1 (coldest = minimal)
```

Output: `std ['a', 'b']` and `min_rank -1` — both match expected behavior (items at-or-below standard = minimal + standard, not full; coldest of {full, minimal} = minimal rank -1). ✓

**Action for dispatcher:** fix the checklist's Section 3.3 step to use `HelpContent` objects and string context names. The implementation itself needs no change.
