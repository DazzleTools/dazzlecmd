# Human Test Checklist: Hidden visibility + hide/expose verbs

**Target version:** v0.8.27 (verbs) + v0.8.28 (`dz kit hide`/`unhide` CLI)
**Ships with commit:** state-system Steps 3, 4a, 4b
**Companion automated tests:** `tests/test_hidden_tools.py` (13), `tests/test_visibility.py` (18), `packages/dazzlecmd-lib/tests/test_entity.py` (live-verb assertions)

## What this is

The visibility ladder made real. A tool can be **Silenced** (no rerooting hints), **Hidden** (omitted from listings but still runnable), or **Shadowed** (gone — short name freed). This checklist verifies the human-facing surface of Hidden + the `hide`/`expose` verbs: the CLI output reads well, `--show-hidden` reveals, and — the load-bearing UX — **a hidden tool still dispatches by name**. Mocks confirm the config writes and the filter logic; only a human at a real terminal confirms the rendering, the reveal flow, and that "hidden but runnable" actually feels right.

## Prerequisites

1. A dazzlecmd checkout with `dz` on PATH (or run `python -m dazzlecmd`).
2. **Isolate your real config** — every step uses a throwaway config so your real `~/.dazzlecmd/config.json` is untouched. Set `DAZZLECMD_CONFIG` to a temp file (see per-shell forms below). Delete it between sections to reset.
3. Pick any real tool FQCN from `dz list` to experiment with (examples below use `core:rn`).

- [ ] **Set up isolation** (pick your shell):

  **cmd.exe**:
  ```cmd
  set DAZZLECMD_CONFIG=%TEMP%\dz-hidden-test.json
  del %DAZZLECMD_CONFIG% 2>nul
  ```

  **PowerShell**:
  ```powershell
  $env:DAZZLECMD_CONFIG = "$env:TEMP\dz-hidden-test.json"
  if (Test-Path $env:DAZZLECMD_CONFIG) { Remove-Item $env:DAZZLECMD_CONFIG }
  ```

  **POSIX**:
  ```bash
  export DAZZLECMD_CONFIG=/tmp/dz-hidden-test.json
  rm -f "$DAZZLECMD_CONFIG"
  ```

## High-Value Verification (~5 minutes)

### HV.1 — Hide a tool, confirm it leaves the listing

Validates: `dz kit hide` writes config and the list/tree render filter drops the tool.

- [ ] **Steps:**
  1. `dz list` — note `rn` (or your chosen tool) is present.
  2. `dz kit hide core:rn`
  3. `dz list`
- [ ] **Expected:** Step 2 prints `Hidden: core:rn` plus a note that it stays dispatchable. Step 3's listing no longer shows `rn`.
- [ ] **Why this matters:** if hiding doesn't remove it from the list, the feature does nothing.

### HV.2 — The hidden tool STILL runs (display-off, dispatch-on)

Validates: the C2 invariant `canonical_dispatch` — Hidden is a render veil, never a dispatch change.

- [ ] **Steps:** with `core:rn` hidden, run it by name: `dz rn --help` (or `dz core:rn --help`).
- [ ] **Expected:** the tool runs normally — hiding changed only its visibility, not its dispatchability.
- [ ] **Why this matters:** this is the whole point of Hidden (vs Shadowed). If a hidden tool can't run, Hidden has collapsed into Shadowed.

### HV.3 — Reveal with `--show-hidden`

Validates: the reveal flag on `dz list` / `dz tree`.

- [ ] **Steps:** `dz list --show-hidden` and `dz tree --show-hidden`.
- [ ] **Expected:** `rn` reappears in both.
- [ ] **Why this matters:** users need a way to see what they've hidden.

### HV.4 — Unhide restores it

Validates: `dz kit unhide` is the clean inverse.

- [ ] **Steps:** `dz kit unhide core:rn` then `dz list`.
- [ ] **Expected:** prints `Unhidden: core:rn`; the tool is back in the default listing.

### HV.5 — Unhide a tool that isn't hidden is graceful

- [ ] **Steps:** `dz kit unhide core:rn` again (already unhidden).
- [ ] **Expected:** prints `'core:rn' was not hidden.` and exits 0 — no traceback.

## Section 1: The ladder is monotone and distinct from Shadowed

### 1.1 Hidden vs Shadowed differ on dispatch

- [ ] **Steps:**
  1. `dz kit hide core:rn` → `dz rn --help` (runs).
  2. `dz kit unhide core:rn`; then `dz kit shadow core:rn` → `dz rn --help`.
- [ ] **Expected:** hidden → runs; shadowed → the short name `rn` no longer resolves (shadow frees it). Reset: `dz kit unshadow core:rn`.

### 1.2 Silenced is the weakest level

- [ ] **Steps:** `dz kit silence core:rn` → `dz list`.
- [ ] **Expected:** `rn` STILL appears (Silenced only suppresses rerooting hints, not display). Reset: `dz kit unsilence core:rn`.

## Section 2: The programmatic verbs (optional, for library users)

### 2.1 hide/expose round-trip via a context

- [ ] **Steps** (cross-shell, Python):
  ```
  python -c "import os; os.environ['DAZZLECMD_CONFIG']=os.path.join(os.environ.get('TEMP','/tmp'),'dz-v.json'); from dazzlecmd.engine import AggregatorEngine; from dazzlecmd_lib.groupable import VisibilityContext; from dazzlecmd_lib.testing import make_tool; e=AggregatorEngine(name='dz',command='dz'); ctx=VisibilityContext(e); t=make_tool(name='rn',_fqcn='core:rn',_short_name='rn',_kit_import_name='core'); r=t.hide(to='hidden',context=ctx); print('hid:',r.previous_state,'->',r.new_state,r.channels_suppressed); print('level:',t.visibility_in(context=ctx)); u=ctx.undo(r); print('after undo:',t.visibility_in(context=ctx))"
  ```
- [ ] **Expected:** `hid: visible -> hidden ('display', 'hints')`, `level: hidden`, `after undo: visible`.

## What the automated tests DON'T cover

- **Shell rendering** of the hide/unhide confirmation lines (Windows codepage, wrapping).
- **Real dispatch** of a hidden tool (the suite asserts the index is untouched; only a human runs `dz rn` and sees it work).
- **The reveal-flow feel** — is `--show-hidden` discoverable; does the hide note point to it clearly?
- **Cross-shell config writes** — the config JSON written under cmd vs PowerShell vs POSIX.
- **Interaction with real silenced/shadowed config** already present in a user's dotfile.
