# Human Test Checklist: safedel `_lib` De-vendoring

**Target version:** v0.10.13
**Ships with commit:** `e246f30` (Tier 1: `dazzle-filekit` + `unctools` deps) + the Tier 2-3 commit (`preservelib` -> `dazzle-preservelib`, delete orphan `core_lib`)
**Companion automated tests:** safedel tool suite **121 passed / 7 skipped** (`projects/core/safedel/tests/`: ctime, xattr, ads, junction, zones, volumes, roundtrip, recover-regression, golden-invariants); `_f_common` adapter **41 passed** (`projects/core/_f_common/tests/test_safe_ops.py`); full suite **1609 passed / 20 skipped** (`pytest tests/ packages/`); byte-gate **10/10**.

## What this is

safedel used to bundle copies of several libraries under `projects/core/safedel/_lib/` and prepend that directory to `sys.path`, so its imports shadowed any installed version. v0.10.13 replaces the **publishable** bundles with real PyPI dependencies — `dazzle-filekit`, `unctools` (win32-only), and `dazzle-preservelib` (the f-cp/f-mv metadata backend, migrated from the `preservelib` import to `dazzle_preservelib`) — and deletes the orphaned `core_lib`. The internal `log_lib`/`help_lib`/`ps1` stay bundled (future `dazzle-loglib`/`dazzle-helplib`), so the `sys.path` shim remains for them.

The automated suite ran on **Windows** against **editable** installs. This checklist covers what that can't: a real **clean-venv install from PyPI**, **POSIX** behavior, the **"backend not installed"** error path, **warning surfacing** after the logger repoint, and **real-file metadata fidelity** — the whole point of a safety-critical (recoverable-delete) tool. Run it before the PyPI publish; Section 1 doubles as the publish runbook's real-install acceptance (AC2).

## Prerequisites

1. A machine with Python 3.9+ and network access to PyPI. Ideally run once on **Windows** and once on **Linux/macOS** (the cross-platform section is the point).
2. A way to build the wheel from a **clean checkout** (`python -m build`) OR the published 0.10.13 wheel once it exists.
3. Throwaway working dirs only — never run destructive steps against real data. Use a scratch dir (below) and `dz safedel`'s recoverable trash.
4. **Reset between sections:** each section is independent; recreate the scratch dir fresh. Recover anything safedel'd with `dz safedel recover last` if needed.

Scratch dir (pick your shell):

**cmd.exe**
```cmd
set SCRATCH=%TEMP%\dz_devendor
if exist %SCRATCH% rmdir /s /q %SCRATCH%
mkdir %SCRATCH%
```
**PowerShell**
```powershell
$env:SCRATCH = "$env:TEMP\dz_devendor"
if (Test-Path $env:SCRATCH) { Remove-Item -Recurse -Force $env:SCRATCH }
New-Item -ItemType Directory $env:SCRATCH | Out-Null
```
**POSIX**
```bash
export SCRATCH=/tmp/dz_devendor
rm -rf "$SCRATCH"; mkdir -p "$SCRATCH"
```

## High-Value Verification (~5 minutes)

If you only have five minutes, run these. They prove the de-vendoring actually works when installed, not just in the dev tree.

### HV.1 — Clean-venv install pulls the de-vendored deps from PyPI

Validates: the wheel declares the right deps and `pip` resolves them from the index (the dev env hid this with editable installs).

- [ ] **Steps** (pick your shell):

  **PowerShell**
  ```powershell
  python -m venv $env:TEMP\dzfresh
  & $env:TEMP\dzfresh\Scripts\python.exe -m pip install --upgrade pip
  & $env:TEMP\dzfresh\Scripts\python.exe -m pip install (Resolve-Path dist\dazzlecmd-0.10.13*.whl)
  & $env:TEMP\dzfresh\Scripts\python.exe -m pip list | Select-String "dazzle|unctools"
  ```
  **POSIX**
  ```bash
  python -m venv /tmp/dzfresh
  /tmp/dzfresh/bin/python -m pip install --upgrade pip
  /tmp/dzfresh/bin/python -m pip install dist/dazzlecmd-0.10.13*.whl
  /tmp/dzfresh/bin/python -m pip list | grep -Ei "dazzle|unctools"
  ```
- [ ] **Expected:** install succeeds; `pip list` shows `dazzle-filekit`, `dazzle-lib` (transitive), `dazzle-preservelib`, and on **Windows** `unctools` (it is `sys_platform == "win32"`, so it is **absent** on POSIX — that is correct).
- [ ] **Why this matters:** if a dep floor or marker is wrong, `pip install dazzlecmd` gives a `dz` whose safedel/f-cp/f-mv crash on first use — the exact failure de-vendoring must not introduce.

### HV.2 — `dz safedel` round-trip in the fresh venv

Validates: the de-vendored `dazzle_filekit` metadata path works from a real install.

- [ ] **Steps** (use the fresh-venv `dz`, e.g. `/tmp/dzfresh/bin/dz` or `...\dzfresh\Scripts\dz.exe`):
  ```
  dz safedel --yes <SCRATCH>/probe.txt    # after creating probe.txt
  dz safedel recover last
  ```
- [ ] **Expected:** file moves to trash, then recovers with content + metadata intact; no `ModuleNotFoundError`.
- [ ] **Why this matters:** safedel is recoverable-delete — a broken metadata backend silently loses fidelity on restore.

### HV.3 — `dz f-cp` / `dz f-mv` work through `dazzle_preservelib`

Validates: the production copy/move path on the migrated backend.

- [ ] **Steps:** create `<SCRATCH>/a.txt`, then `dz f-cp <SCRATCH>/a.txt <SCRATCH>/b.txt`, then `dz f-mv <SCRATCH>/b.txt <SCRATCH>/c.txt`.
- [ ] **Expected:** both report `[OK] ... exit=0`; `b.txt` content matches `a.txt`; after the move `c.txt` exists and `b.txt` is gone.
- [ ] **Why this matters:** these are the only first-party consumers of `dazzle-preservelib`; the 0.4->0.8 migration must not change their semantics.

### HV.4 — "Backend not installed" refuses with the corrected message

Validates: the hard-fail sentinel + the personal-path error fix.

- [ ] **Steps:** in a venv where `dazzle-preservelib` is **NOT** installed (or temporarily uninstall it), run `dz f-cp <SCRATCH>/a.txt <SCRATCH>/b.txt`.
- [ ] **Expected:** the op **refuses** (non-zero exit, no copy made — it does NOT silently fall back to a lossy copy) and prints `Install via: pip install dazzle-preservelib`. It must **not** print any developer-specific local path.
- [ ] **Why this matters:** a silent shutil fallback would drop ACLs/ctime without telling the user; and a personal install path shipping publicly is wrong.

### HV.5 — The still-vendored remainder is unaffected

Validates: `log_lib` (still under `_lib/`, still loaded via the `sys.path` shim) works.

- [ ] **Steps:** `dz safedel status` and `dz safedel list` (these route through safedel's `log_lib`-backed output).
- [ ] **Expected:** normal, unchanged output and logging; no import error for `log_lib`.
- [ ] **Why this matters:** Tier 2-3 deleted `preservelib`/`core_lib` from `_lib/`; if that broke the shim or orphaned something `log_lib` needs, safedel's output breaks.

## Section 1: Clean install from PyPI / wheel (the de-vendoring's core risk)

### 1.1 Transitive resolution is complete

- [ ] **Steps:** in the fresh venv from HV.1, run `dz --version` and `dz list | <count tools>`.

  **PowerShell:** `dz list | Measure-Object -Line`
  **POSIX:** `dz list | wc -l`
- [ ] **Expected:** `dz --version` prints `0.10.13`; `dz list` is non-empty (tools present per #58). No `ModuleNotFoundError` for `dazzle_filekit`, `dazzle_preservelib`, `dazzle_lib`.
- [ ] **Check:** `pip show dazzle-preservelib` reports >= 0.8.1; `pip show dazzle-filekit` >= 0.3.2.

### 1.2 No vendored shadow remains for the de-vendored libs

- [ ] **Steps:** in the fresh venv, `python -c "import dazzle_filekit, dazzle_preservelib; print(dazzle_filekit.__file__); print(dazzle_preservelib.__file__)"`.
- [ ] **Expected:** both paths point into the venv's `site-packages` — **not** into any `safedel/_lib/` directory (the installed wheel must not ship `_lib/dazzle_filekit` or `_lib/preservelib`; those were removed/were untracked).

## Section 2: Cross-platform (run on Linux/macOS)

### 2.1 unctools absence is benign on POSIX

- [ ] **Steps:** confirm `unctools` is NOT installed (`pip show unctools` -> not found, by the win32 marker). Then run a normal `dz fixpath <some/relative/path>` (a non-UNC path) and a `dz safedel` round-trip.
- [ ] **Expected:** everything works; the UNC->local conversion code path (which lazily imports `unctools`) is simply never reached, and its `try/except ImportError` swallows the absence. No crash, no warning about `unctools`.

### 2.2 xattr / mode-bit / mtime preservation on POSIX

- [ ] **Steps:** create a file, set an extended attribute (`setfattr -n user.test -v hello <SCRATCH>/x.txt` on Linux) and a non-default mode (`chmod 640`). `dz f-cp <SCRATCH>/x.txt <SCRATCH>/y.txt`. Inspect `y.txt`.
- [ ] **Expected:** `y.txt` preserves the mode bits, mtime, and the `user.test` xattr (`getfattr -d y.txt`). This exercises `dazzle_preservelib`'s `_collect_unix_xattrs` / `_apply_unix_xattrs` for real (the private APIs the migration depends on).

## Section 3: Backend-not-installed error path (detailed)

### 3.1 Refuse, don't degrade — for both f-cp and f-mv

- [ ] **Steps:** in a venv without `dazzle-preservelib`, run both `dz f-cp` and `dz f-mv` on a real source file.
- [ ] **Expected:** both refuse (non-zero exit), the source is untouched, NO partial/lossy copy is produced, and the message names `pip install dazzle-preservelib`. Cross-check the exit code is the system-error code, not a success.

## Section 4: Warning surfacing after the logger repoint

### 4.1 Non-fatal preservation failures still reach the user

- [ ] **Steps:** induce a non-fatal metadata failure during a copy — e.g. copy a file whose source ACL/owner cannot be reproduced at the destination (a cross-user or restricted-ACL scenario on Windows; or copy across filesystems where some attr can't be set on POSIX). `dz f-cp <restricted-source> <SCRATCH>/out.txt`.
- [ ] **Expected:** the copy still succeeds for content, AND the non-fatal preservation warning is **surfaced** in dz's output (e.g. a note that ctime/ACL wasn't restored). The capture now listens on the `dazzle_preservelib` logger — if it were still on `"preservelib"`, this warning would be **silently dropped**.
- [ ] **Why this matters:** the logger repoint is the highest silent-failure risk in the migration; this is the test that proves it didn't go deaf.

## Section 5: Real metadata fidelity (eyeball it)

### 5.1 safedel delete -> recover preserves real metadata

- [ ] **Steps (Windows):** create a file, set a creation time / an alternate data stream (`echo secret > x.txt:hidden`). `dz safedel --yes x.txt`; `dz safedel recover last`. Inspect ctime and the ADS (`dir /r`, `more < x.txt:hidden`).
- [ ] **Expected:** ctime and the ADS survive the round-trip identically.

### 5.2 f-cp/f-mv preserve real metadata

- [ ] **Steps:** copy and move files carrying real ACLs (Windows) / xattrs+mode (POSIX); compare source vs destination metadata.
- [ ] **Expected:** byte-identical metadata where the platform allows; any non-preservable attribute surfaces a warning (Section 4), never a silent loss.

## Section 6: Still-vendored remainder

### 6.1 `_lib/` contents and the shim

- [ ] **Steps:** in a dev checkout, `ls projects/core/safedel/_lib/` (POSIX) / `dir` (Windows).
- [ ] **Expected:** only `__init__.py`, `log_lib/`, `help_lib/`, `ps1/` remain — no `preservelib/`, no `core_lib/`, no `dazzle_filekit/`, no `unctools/`.
- [ ] **Check:** `dz safedel --help` and a real `dz safedel` op work (the `sys.path` shim still serves `log_lib`).

## What the automated tests DON'T cover (why this checklist exists)

- **Real clean-venv install from PyPI** — dev env uses editable installs; dep markers/floors only get exercised by a real `pip install`.
- **POSIX** — automated runs were Windows-only; `unctools` absence + Unix xattr/mode preservation are untested there.
- **The not-installed refuse path with the real message** — unit tests mock the import; they don't render the actual user-facing error string.
- **Logger repoint warning surfacing** — unit tests assert capture works, but on a synthetic logger; the real lib's `getLogger(__name__)` tree is only proven live.
- **Real metadata fidelity on real ACLs/ADS/xattrs** — mocks verify the call, not the OS-level result.

## Reporting issues found

1. Note the section/step number and the OS.
2. Capture the exact command, output, and exit code.
3. For metadata failures, save before/after attribute dumps.
4. File against #58 (or a new issue) referencing this checklist and the triggering commit.
