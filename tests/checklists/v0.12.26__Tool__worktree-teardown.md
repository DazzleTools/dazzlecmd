# Human Test Checklist: dz worktree-teardown

**Target version:** dazzlecmd 0.12.26-alpha with dazzlecmd-lib 0.10.38-alpha
**Ships with commit:** `v0.12.26 feat(worktree-teardown): remove a git worktree without deleting through its links`
**Companion automated tests:** 27 -- dazzlecmd-lib `tests/test_core_safedel_worktree.py` (17, the teardown itself); dazzlecmd `src/dazzlecmd/projects/dazzletools/worktree-teardown/tests/test_worktree_teardown.py` (10, the command line).

## What this is

`git worktree remove` deletes through a junction or symlink inside a worktree and empties what it points at (measured on git 2.52.0.windows.1: with `--force`, and without it when the linked folder is gitignored). On 2026-11-17 that emptied two real folders. `dz worktree-teardown` is the replacement. The automated tests run it on temporary repositories with a temporary trash store; this checklist is a person running the real command on a scratch repository, to see the plan, the prompt, the report, and that the link's target really is untouched.

## Prerequisites

1. `python -c "import dazzlecmd_lib; print(dazzlecmd_lib.__version__)"` shows 0.10.38 or later. If it is older, the command prints `worktree-teardown needs dazzlecmd-lib 0.10.38 or later` and exits 1 (Section 5 checks that).
2. **Work only on the scratch repository built below**, under your temp directory. Do not point this checklist at a real worktree.
3. **A successful teardown writes to your real safedel trash store** (two batches: the link, then the folder). They are scratch content; note the batch names printed in the report. Cleaning them up is your choice, by you, with `dz safedel clean`.
4. **Never run `git worktree remove`** on the fixture, here or anywhere.
5. Every git command names its repository with `-C` and commits unsigned (`-c commit.gpgsign=false`), so nothing lands in a real repository and no signing prompt appears.

### Build the fixture

**PowerShell** (Windows; the link is a junction):
```powershell
$r = "$env:TEMP\wt-teardown-check"
git init -q -b main "$r\proj"
Set-Content "$r\proj\README.md" x; Set-Content "$r\proj\.gitignore" "private/"
git -C "$r\proj" add README.md .gitignore
git -C "$r\proj" -c user.email=t@example.com -c user.name=tester -c commit.gpgsign=false commit -q -m init
New-Item -ItemType Directory -Force "$r\proj\private" | Out-Null
Set-Content "$r\proj\private\notes.md" notes
git -C "$r\proj" worktree add -q -b feat "$r\proj__feature" main
New-Item -ItemType Junction -Path "$r\proj__feature\private" -Target "$r\proj\private" | Out-Null
Set-Content "$r\proj__feature\work.txt" "uncommitted work"
```

**POSIX / Git Bash** (the link is a symlink):
```bash
r="${TMPDIR:-/tmp}/wt-teardown-check"
git init -q -b main "$r/proj"
echo x > "$r/proj/README.md"; echo "private/" > "$r/proj/.gitignore"
git -C "$r/proj" add README.md .gitignore
git -C "$r/proj" -c user.email=t@example.com -c user.name=tester -c commit.gpgsign=false commit -q -m init
mkdir -p "$r/proj/private" && echo notes > "$r/proj/private/notes.md"
git -C "$r/proj" worktree add -q -b feat "$r/proj__feature" main
ln -s "$r/proj/private" "$r/proj__feature/private"
echo "uncommitted work" > "$r/proj__feature/work.txt"
```

(cmd.exe: run the PowerShell block with `powershell -NoProfile -File`, or use Git Bash; the commands after this point are the same in every shell apart from the path prefix.)

## High-Value Verification (~5 minutes)

### HV.1 -- The plan, with nothing changed

- [ ] **Steps:** `dz worktree-teardown --dry-run <r>/proj__feature`
- [ ] **Expected:** the worktree and its main repository; one `link (junction)` (or `symlink`) line with its target and `will NOT be touched`; five numbered steps ending in `git worktree prune`; last line `worktree-teardown: DRY-RUN 1 link(s) and the folder would be removed`; exit code 0.
- [ ] **Check:** `proj__feature\private` and `proj__feature\work.txt` are still there.
- [ ] **Why this matters:** the plan is the only chance to see that the tool found the link before it acts.

### HV.2 -- Nobody at the keyboard and no `--yes`: refused

- [ ] **Steps:** run it with input closed -- cmd.exe `dz worktree-teardown <path> < NUL`; PowerShell `$null | dz worktree-teardown <path>`; POSIX `dz worktree-teardown <path> < /dev/null`.
- [ ] **Expected:** last line `worktree-teardown: REFUSED not interactive and --yes was not given`; exit code 3; nothing changed.
- [ ] **Why this matters:** a destructive command must not act, or report success, when nobody answered.

### HV.3 -- The teardown

- [ ] **Steps:** `dz worktree-teardown --yes <r>/proj__feature`
- [ ] **Expected:** `done:` lines in this order -- removed the link (target untouched), checked every link target is intact, moved the folder into the trash, checked it is gone and the targets are intact, `git worktree prune`; then the two batch names; last line `worktree-teardown: DONE <path>`; exit code 0.
- [ ] **Check:**
  - `proj__feature` no longer exists;
  - `proj\private\notes.md` still exists with its content -- **this is the whole point**;
  - `git -C <r>/proj worktree list` shows only the main checkout.
- [ ] **Why this matters:** on 2026-11-17 the equivalent of this step emptied `proj\private`.

### HV.4 -- It can be brought back

- [ ] **Steps:** `dz safedel recover <second batch name>` (the folder), then `git -C <r>/proj worktree repair <r>/proj__feature`.
- [ ] **Expected:** the folder is back with `work.txt` ("uncommitted work"); `git -C <r>/proj worktree list` lists it again. The `private` link is not inside it (it is in the first batch; `dz safedel recover <first batch name>` re-creates it).
- [ ] **Why this matters:** "to the trash" has to mean recoverable, uncommitted work included.

### HV.5 -- A main checkout is refused

- [ ] **Steps:** `dz worktree-teardown --yes <r>/proj`
- [ ] **Expected:** exit code 3; the message says this is a repository's main checkout, not a linked worktree; nothing changed.

## Section 1: The prompt (MANUAL -- a person types)

- [ ] Rebuild the fixture if needed. In a real terminal: `dz worktree-teardown <r>/proj__feature`. The plan is shown, then `Proceed? [y/N]:`. Press Enter: last line `worktree-teardown: REFUSED declined at the prompt`, exit 3, nothing changed. Run again and type `y`: it proceeds.
- [ ] Try it in Windows Terminal, the classic console, and Git Bash (mintty). If one refuses at once with "not interactive", report the terminal.

## Section 2: Things that are not worktrees

- [ ] A plain folder (`mkdir <r>/plain`): refused, exit 3, "not a git worktree".
- [ ] A path that does not exist: refused, exit 3.
- [ ] The link itself (`<r>/proj__feature/private`): refused, exit 3.

## Section 3: More than one link

- [ ] Add a second link deeper in the worktree to another scratch folder (same commands as in the fixture, e.g. `proj__feature\sub\private` -> a new `<r>\elsewhere`). `--dry-run` lists both, the deeper one first. After `--yes`, both targets are intact and three batches are listed.

## Section 4: Reading the report cold

- [ ] Give the HV.1 and HV.3 output to someone who has not seen the tool. Can they say what was removed, what was not touched, and how to get it back?

## Section 5: An older library

Only if you can arrange dazzlecmd 0.12.26 with a dazzlecmd-lib older than 0.10.38.

- [ ] `dz worktree-teardown --dry-run <any path>` prints `worktree-teardown needs dazzlecmd-lib 0.10.38 or later (...)`, last line `worktree-teardown: ERROR dazzlecmd-lib is too old`, exit code 1, and changes nothing.

## What the automated tests DO cover

| Where | Tests | Areas |
|---|---|---|
| dazzlecmd-lib `tests/test_core_safedel_worktree.py` | 17 | The plan; refusals; the order of steps; links at depth and with the same name; a target that changes part-way stops the teardown before the folder moves; a link that cannot be removed; a failed prune; that no git command other than `worktree prune` is issued; the link registry |
| dazzlecmd `.../worktree-teardown/tests/test_worktree_teardown.py` | 10 | Consent, the prompt, the dry run, exit codes, the last-line verdict, a stopped teardown, an older library |

## What the automated tests DON'T cover

- **A worktree on a different drive from the trash store.** The folder is then copied, not renamed. The links are already gone by that point, so nothing is copied through, but the copy does not carry creation times.
- **A worktree that something has open** (an editor, a terminal whose current directory is inside it). The move can fail after the links were removed; the report then says "STOPPED part-way" (exit 4) and lists the batch holding the links. `dz unlockit <path>` names what holds it.
- **A real, large worktree** (build output, `node_modules`): how long the search for links takes.
- **Real consoles** (Section 1), and how the plan's long paths wrap.
- **Git versions other than 2.52**, and a worktree created with relative paths (`worktree.useRelativePaths`).
- **The link registry on a real machine:** nothing writes `~/.safedel/junctions.json` yet.

## Reporting issues found

Note the section and step, the exact command, the full output and the exit code, your git version (`git --version`), terminal and shell, and file an issue referring to this checklist and version 0.12.26.

## Cleanup

- [ ] Batches created in your real trash store (HV.3: two; Section 3: three): leave them to age out, or remove them yourself with `dz safedel clean <batch-name> --force` at a console.
- [ ] Delete the scratch folder `wt-teardown-check` from your temp directory by hand. If a worktree in it still exists, tear it down with this tool or delete the whole scratch folder in a file manager -- not with `git worktree remove`.
