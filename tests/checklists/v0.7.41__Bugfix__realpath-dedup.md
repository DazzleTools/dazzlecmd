# Human Test Checklist: v0.7.41 — Realpath-based auto-aliasing (closes #65)

**Target version:** v0.7.41
**Ships with commit:** TBD
**Companion automated tests:** `tests/test_engine_recursive.py::TestRealpathDedup` (9 new tests; 1 POSIX-only skipped on Windows). Total suite: 1068 passed, 14 skipped.

## What this is

When the discovery path reaches the same on-disk script via two distinct FQCNs — junction loop, symlink, or two aggregators that cross-embed each other with shared physical files — pre-v0.7.41 the engine registered both FQCNs as separate canonicals, and every display surface (`dz list`, `dz tree`, `dz kit list`, custom help epilogs) showed duplicate rows.

v0.7.41 implements Solution B from the dev-workflow analysis: realpath-based auto-aliasing at discovery time. Only the shortest FQCN registers as canonical; the rest register as aliases with `source="auto-realpath"`. Dispatch via any FQCN still works (alias mechanism forwards to canonical). Display surfaces collapse to one row per physical script automatically.

**Important scope note**: this fix applies ONLY when the duplicate FQCNs `realpath()` to the SAME file. Two physically separate copies of the same logical tool (e.g., a submodule embedded at commit X plus a standalone install at commit Y) are NOT collapsed — they really are different files. That's a separate "two installs of the same logical tool" problem, not realpath equality.

## Prerequisites

1. dazzlecmd installed in editable mode (`pip install -e .`)
2. PowerShell or admin cmd.exe for creating Windows junctions (POSIX users can use `ln -s`)
3. A temp directory you don't mind cluttering — the synthetic setup uses `%TEMP%` / `/tmp`
