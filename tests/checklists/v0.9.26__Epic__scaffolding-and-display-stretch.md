## What this is

One verification pass over the stretch: **(1)** the new scaffolder (`dz new kit` / `dz new aggregator`, v0.9.20+v0.9.25), **(2)** the display arc (kit-list wrap+bold, tree/-h width budgets, legend, v0.9.21–24), **(3)** the kit-list renderer unification (v0.9.26 — one renderer in the lib, dz's custom handler deleted, consumers upgraded). Covers what mocks/goldens can't: real-terminal rendering, real generated-project execution, and the by-hand feel.

**SAFETY:** all fs-mutating steps run in throwaway %TEMP% sandboxes. Never run `dz mode switch/restore` on real tools; never edit real configs (use an isolated `DAZZLECMD_CONFIG` for display checks: `{"list_view":"default","_schema_version":1,"active_kits":["media","wtf"],"disabled_kits":[]}`); deletions via `dz safedel --yes`; leave `git status` untouched.

## High-Value Verification (~6 minutes)

### HV.1 — Generated aggregator works end-to-end
- [ ] **Steps** (PowerShell, in a temp dir): `cd $env:TEMP; mkdir hv1; cd hv1; dz new aggregator MyTools --with-starter; cd MyTools; $env:PYTHONPATH="src"; python -m mytools.cli list; python -m mytools.cli hello; python -m pytest tests -q`
- [ ] **Expected:** `list` shows `hello`; dispatch prints the starter stub; the generated smoke test passes.
- [ ] **Why:** the whole v0.9.20 promise — a working aggregator out of the box.

### HV.2 — Inside-an-aggregator warning (v0.9.25)
- [ ] **Steps:** from `C:\code\dazzlecmd\github`: `dz new aggregator ZZTest` → read stderr → then `dz safedel ZZTest --yes` to clean up.
- [ ] **Expected:** the `Note: you are inside the aggregator at ...` warning on stderr; project still created; **no existing file touched** (`git status` unchanged apart from the untracked ZZTest before cleanup).

### HV.3 — `dz kit list` (the unified renderer): summary + drill-in + virtual
- [ ] **Steps** (isolated config): `dz kit list`, `dz kit list core`, `dz kit list f`
- [ ] **Expected:** summary = bold kit names, `[status]` brackets, wrapped descriptions (incl. `wtf`'s aggregator.json description); `core` drill-in = data-computed columns, wrapped descriptions; `f` drill-in = the alias table (`f:rm -> core:safedel`, etc.). **Identical to v0.9.25 output** (the unification is byte-preserving — goldens prove it headlessly; eyeball the real-terminal render).

### HV.4 — Width budgets: `dz tree` and `dz -h`
- [ ] **Steps:** in a real (wide) terminal: `dz tree`, `dz -h`
- [ ] **Expected:** tree descriptions extend to the terminal edge then `...` (no fixed-57 waste); in `-h`, the long-named `claude-session-metadata` row stays ONE line with `...` — no mid-word spill onto the next line.

### HV.5 — `dz new kit` registers correctly
- [ ] **Steps:** in a sandbox aggregator (HV.1's MyTools): `python -m mytools.cli ...` n/a — instead from the real repo: `dz new kit zztestkit --with-starter` → inspect `projects/zztestkit/.kit.json` + `kits/zztestkit.kit.json` → `dz kit enable zztestkit` → `dz list` shows `zztestkit:hello` → cleanup: `dz kit disable zztestkit; dz safedel projects/zztestkit kits/zztestkit.kit.json --yes`.
- [ ] **Expected:** manifest has `tools: ["zztestkit:hello"]`; pointer `always_active: false`; tool discoverable after enable.

### HV.6 — Consumer upgrade (the unification's gift)
- [ ] **Steps:** in the wtf checkout (or any lib consumer): run its kit list (`wtf kit list` if installed).
- [ ] **Expected:** it now shows `[status]` brackets + the full drill-in (previously the weaker legacy view). MANUAL — needs the consumer on the updated lib.
