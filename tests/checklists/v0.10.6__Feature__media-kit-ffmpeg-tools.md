# Human Test Checklist: media kit (ffmpeg-style tools)

**Target version:** 0.1.0 (media kit)
**Ships with commit:** TBD — dazzlecmd is intentionally uncommitted until it finishes generalizing; reference point is the `dz git-snapshot` named `20260525-175910_media-kit-phase1-vid2gif-vidresize-pre-phase-2-omn`.
**Companion automated tests:** none yet. Pre-ship verification to date is mechanical only: `py_compile` (7/7 tools), `dz` discovery + dispatch + `--help` (7/7), and one `vid2gif` end-to-end run. **Until a pytest suite exists, this checklist is the primary functional verification.**

## What this is

The `media` kit bundles seven ffmpeg/audio tools under `dz`: `vid2gif`, `vidresize`, `img2vid`, `crossfade`, `song-to-vid`, `vid-preview-maker`, and `mp3me`. Six wrap `ffmpeg`/`ffprobe`; `mp3me` wraps `flac`/`lame`/`metaflac`. This document is what a human runs to confirm the tools actually produce correct media (not just that they dispatch) — covering real subprocess behavior, output dimensions/sizes, intermediate-file cleanup, interactive-prompt removal, and the external-binary dependencies that mocks can't exercise.

## Planning lineage

## Prerequisites

1. **OS:** Windows is the primary target (these tools are used there); they are written cross-platform.
2. **Binaries on PATH:**
   - `ffmpeg` and `ffprobe` — required by all six video/gif tools.
   - `gifsicle` — used by `vid2gif` for the optimize/`--lossy` pass (it degrades gracefully if absent).
   - `flac`, `lame`, `metaflac` — required by `mp3me`. These are **not** bundled; on this machine they live beside the FLAC library, so **run `mp3me` from that folder** (Windows resolves bare exe names from the current directory).
   - Verify (cross-shell):
     - **cmd.exe:** `where ffmpeg & where ffprobe & where gifsicle`
     - **PowerShell:** `Get-Command ffmpeg,ffprobe,gifsicle | Select Name,Source`
     - **POSIX:** `command -v ffmpeg ffprobe gifsicle`
3. **Enable the kit** (persists in your dz user config):
   ```
   dz kit enable media
   dz kit list media
   ```
4. **Test assets** (supply your own; examples below use placeholders):
   - A short video — referred to as `IN.mp4`.
   - Two or more images — `a.jpg`, `b.jpg` — plus a short audio file `song.mp3`.
   - An audio file **with embedded cover art** for `song-to-vid`.
   - A folder of `.flac` files for `mp3me`.
5. **Work in a scratch directory.** Several tools write intermediate files (e.g. `video_segment_*.mp4`, `prepared_image_*.png`, `padded_image.jpg`) into the **current working directory**. `cd` into an empty throwaway folder first.
6. **Reset between sections:** delete generated outputs and stray intermediates (see Cleanup).

## High-Value Verification (~5 minutes)

If you only have 5 minutes, run these. If any fail, the kit is broken and the detailed sections won't save you.

### HV.1 — Kit discovers and all 7 tools dispatch

Validates: kit registration, manifest correctness, dispatch wiring.

- [ ] **Steps** (cross-shell safe, `dz` only):
  ```
  dz kit list media
  ```
- [ ] **Expected:** `Kit: media [enabled]` and exactly **7 tools**: img2vid, mp3me, song-to-vid, vid-preview-maker, vid2gif, crossfade, vidresize.
- [ ] **Why this matters:** If the kit doesn't list 7, a manifest or the `.kit.json` roster is wrong and nothing else works.

### HV.2 — vid2gif end-to-end (the flagship recipe)

Validates: palettegen -> paletteuse -> gifsicle pipeline, sizing, intermediate cleanup.

- [ ] **Steps:**
  ```
  dz vid2gif IN.mp4 --scale 0.5 --lossy 80 -o out.gif -y
  ```
- [ ] **Expected:** Prints `[1/2 palette]`, `[2/2 gif]`, `[gifsicle]`, then `done: out.gif (... MB)`. `out.gif` plays at ~half the source width.
- [ ] **Check:** No `out_palette.png` or `out_raw.gif` left behind (auto-cleaned unless `--keep-raw`).
  - **cmd.exe:** `dir out*`  **PowerShell:** `Get-ChildItem out*`  **POSIX:** `ls -l out*`
- [ ] **Why this matters:** This is the headline tool and exercises three chained subprocesses + cleanup.

### HV.3 — vidresize resizes by width, AR preserved

Validates: ffprobe fps detect, scale filter, metadata strip.

- [ ] **Steps:**
  ```
  dz vidresize -i IN.mp4 -W 640 -o small.mp4 -y
  ```
- [ ] **Expected:** `[info] detected source fps: ...`, an ffmpeg run, `done: small.mp4`. `small.mp4` is 640px wide with height auto-derived (even number).
- [ ] **Why this matters:** Confirms the comfyui port works and AR math is correct.

### HV.4 — img2vid builds a slideshow from images + audio

Validates: multi-image sequencing, ffprobe duration (was mutagen), non-interactive path.

- [ ] **Steps:**
  ```
  dz img2vid -i a.jpg -i b.jpg:50% -a song.mp3 -o slideshow.mp4
  ```
- [ ] **Expected:** Builds `slideshow.mp4`; prints `Final video saved to slideshow.mp4`. No hang waiting for input.
- [ ] **Why this matters:** Confirms the mutagen->ffprobe swap and the removed `input()` prompt.

### HV.5 — song-to-vid turns a track into a video

Validates: album-art extraction + still-image loop.

- [ ] **Steps:**
  ```
  dz song-to-vid track_with_cover.mp3 -o songvids
  ```
- [ ] **Expected:** `songvids/track_with_cover.mp4` created from the embedded art. If the track has **no** embedded art, it logs a skip warning and exits non-zero (expected).
- [ ] **Why this matters:** Confirms the shell=True -> list-form conversion didn't break the two-step pipeline.

### HV.6 — mp3me transcodes a FLAC tree to MP3

Validates: the verbatim whatmp3 logic under dz dispatch (argv passthrough, cwd binary resolution).

- [ ] **Steps** (run from the folder containing `flac`/`lame`/`metaflac`):
  ```
  dz mp3me --320 -n <flac-album-dir>
  ```
  (`-n` skips torrent creation.)
- [ ] **Expected:** Prints `Encoding with 320 started...` then `finished`; a new `<album> (320)` folder of `.mp3`s appears with tags copied.
- [ ] **Why this matters:** Confirms the OptionParser port dispatches and that bare-name binaries resolve from cwd.

After HV.1–HV.6 pass, you have high confidence the kit shipped correctly. Detailed sections follow.

## Section 1: vid2gif (~5 min)

### 1.1 Sizing variants
- [ ] `dz vid2gif IN.mp4 -W 800 -o w800.gif -y` -> gif is 800px wide.
- [ ] `dz vid2gif IN.mp4 -H 400 -o h400.gif -y` -> gif is 400px tall.
- [ ] `dz vid2gif IN.mp4 --scale 0.25 -o quarter.gif -y` -> quarter-size.
- [ ] **Mutual exclusion:** `dz vid2gif IN.mp4 --scale 0.5 -W 800` -> argparse error (not both).

### 1.2 fps + trim
- [ ] `dz vid2gif IN.mp4 --fps 12 --start 1 --duration 2 -o clip.gif -y` -> ~2s gif at 12fps starting 1s in.

### 1.3 Dither / colors / gifsicle toggles
- [ ] `dz vid2gif IN.mp4 --dither bayer --colors 128 -o bayer.gif -y` -> runs, smaller palette.
- [ ] `dz vid2gif IN.mp4 --no-optimize -o raw.gif -y` -> no `[gifsicle]` line; ffmpeg output is final.
- [ ] `dz vid2gif IN.mp4 --keep-raw -o keep.gif -y` -> `keep_palette.png` and `keep_raw.gif` are **left in place**.

### 1.4 Guards
- [ ] Output exists without `-y` -> error "output exists (use -y to overwrite)".
- [ ] `--colors 999` -> error "--colors must be 2-256".
- [ ] Missing input -> error "input not found".

## Section 2: vidresize (~5 min)

### 2.1 Height resize + fps override
- [ ] `dz vidresize -i IN.mp4 -H 720 --fps 30 -o h720.mp4 -y` -> 720px tall, 30fps.
### 2.2 Audio injection (needs `song.mp3`)
- [ ] `dz vidresize -i IN.mp4 -W 640 --audio song.mp3 -afi 1 -afo 2 -o withaudio.mp4 -y` -> source audio replaced; 1s fade-in, 2s fade-out; output ends at video length.
### 2.3 Metadata
- [ ] Default strips metadata. Verify (cross-shell): `ffprobe -v error -show_entries format_tags -of default=nk=1:nw=1 h720.mp4` shows no leftover `encoder=Lavf...`.
- [ ] `--keep-metadata` retains tags.
### 2.4 --as-phone (only if exiftool present)
- [ ] `dz vidresize -i IN.mp4 -W 640 --as-phone iphone-8 -o phone.mp4 -y` -> applies preset; `[patch] zeroed CompressorName ...`. If exiftool absent -> clear error with install hints.

## Section 3: img2vid + crossfade (~5 min)

> These write intermediates (`prepared_image_*.png`, `video_segment_*.mp4`, `video_output_*.mp4`) to the CWD. Run in a scratch dir.

### 3.1 img2vid ordering + --strict
- [ ] `dz img2vid -i a.jpg -i b.jpg:30s -i c.jpg:1m -a song.mp3 -o seq.mp4` -> ordered slideshow.
- [ ] Out-of-order times **warn and proceed** by default: `dz img2vid -i a.jpg -i b.jpg:1m -i c.jpg:30s -a song.mp3 -o oo.mp4` prints "not in chronological order ... Proceeding".
- [ ] `--strict` aborts instead: same command + `--strict` -> prints "aborting" and exits non-zero, **no prompt/hang**.
- [ ] `< 2` images -> error "needs at least two -i/--image".
- [ ] Cleanup: after a successful non-`-d` run, no `prepared_image_*`/`video_segment_*` remain. With `-d`, they remain.

### 3.2 crossfade (2-image shortcut)
- [ ] `dz crossfade -i a.jpg -i b.jpg:50% -a song.mp3 -o cross.mp4` -> single crossfade.
- [ ] `< 2` images -> error "needs exactly two".

## Section 4: song-to-vid (~3 min)

- [ ] Multiple files: `dz song-to-vid t1.mp3 t2.flac -o vids` -> one `.mp4` per track that has art.
- [ ] Unsupported extension (e.g. `.txt`) -> logged as "Invalid or unsupported file", skipped.
- [ ] No-art track -> "No album art found ... Skipping"; exits non-zero if nothing was produced.

## Section 5: vid-preview-maker (~3 min)

> Writes `preview_audio.wav`, `first_segment.mp4`, `padded_image.jpg`, `updated_second_segment.mp4`, `video_output.mp4`, `final_output.mp4` to CWD and **reuses them if present** (resume cache — they are NOT auto-deleted). Run in a scratch dir and clear it between runs.

- [ ] `dz vid-preview-maker IN.mp4 banner.png` -> `final_output.mp4`: first segment, crossfade into the banner, audio fades out near the end.
- [ ] Missing banner image -> error "banner image not found".
- [ ] Re-running without clearing the scratch dir **reuses** existing intermediates (fast, by design). Confirm you understand this before re-testing — delete them to force a fresh build.

## Section 6: mp3me (~5 min)

> Run from the folder where `flac`/`lame`/`metaflac` live. `mp3me` is a verbatim port of `whatmp3` — same flags and behavior.

- [ ] `dz mp3me --help` -> OptionParser help with `--320 --V0 --V2 --Q8 --AAC --ALAC --FLAC` format flags.
- [ ] `dz mp3me` (no args) -> "Incorrect number of arguments" (proves argv passthrough).
- [ ] `dz mp3me <album>` (no format) -> "You need to provide at least one format..." and **exits 1** (was a bare `exit()` in the original).
- [ ] `dz mp3me --320 -n <album>` -> `<album> (320)` folder of MP3s with tags; **no `.torrent`** created.
- [ ] `dz mp3me --V0 --V2 -n <album>` -> two output folders.
- [ ] **Torrent default caveat:** without `-n`, `mp3me` will attempt to build a `.torrent` via `mktorrent` using the (dead What.CD) tracker baked into the script. Use `-n` unless you specifically want a torrent.

## What the automated tests DO cover

| Area | How | Status |
|---|---|---|
| Syntax / import sanity | `py_compile` all 7 tools | 7/7 pass |
| Kit discovery + dispatch | `dz kit list media`, `dz <tool> --help` | 7/7 pass |
| vid2gif full pipeline | one end-to-end run (scale 0.5, lossy 80) | pass (5.5 MB output) |

There is **no pytest suite yet** — adding one (mocked subprocess + a couple of real-asset integration tests) is the obvious next step.

## What the automated tests DON'T cover

- Whether output media is actually **correct** (dimensions, fps, fades, crossfades, audio sync, tag preservation) — only a human eyeballing the files catches this.
- Real `ffmpeg`/`ffprobe`/`gifsicle`/`flac`/`lame`/`metaflac` behavior and exit codes.
- Intermediate-file creation/cleanup in the CWD (img2vid, crossfade, vid-preview-maker).
- `mp3me`'s reliance on cwd-resolved binaries and its torrent-by-default behavior.
- The removed interactive prompt in `img2vid` (no hang under non-interactive dispatch).
- Windows codepage / terminal rendering of the `[1/2 palette]`-style status lines.
- Cross-platform behavior (these are exercised mostly on Windows).

## Reset & cleanup

- [ ] Delete generated outputs and stray intermediates from your scratch dir:
  - **cmd.exe:** `del out*.gif small.mp4 *.mp4 prepared_image_*.png video_segment_*.png 2>nul`
  - **PowerShell:** `Remove-Item out*.gif,*.mp4,prepared_image_*.png,video_segment_*.mp4,padded_image.jpg,preview_audio.wav -ErrorAction SilentlyContinue`
  - **POSIX:** `rm -f out*.gif *.mp4 prepared_image_*.png video_segment_*.mp4 padded_image.jpg preview_audio.wav`
- [ ] If you don't want the kit active afterward: `dz kit disable media`.
- [ ] `mp3me` output folders (`<album> (320)` etc.) and any `.torrent` files: delete manually if unwanted.
