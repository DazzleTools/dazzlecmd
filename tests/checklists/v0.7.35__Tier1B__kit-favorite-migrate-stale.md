# Human Test Checklist: v0.7.35 — Tier 1B — `dz kit favorite --migrate-stale`

**Target version:** v0.7.35 **Ships with commit:** TBD (Tier 1 commit 7, the kit-favorite migration flow) **Companion automated tests:** 14 new tests in `tests/test_cli_kit.py::TestKitFavoriteMigrateStale` + `TestSuggestFavoriteReplacement`. Total suite: 973 passed, 13 skipped.

## What this is

v0.7.35 adds an interactive maintenance flow for stale favorites. The v0.7.27 commit shipped detection-and-warning for stale favorites at resolution time — `dz kit favorite --migrate-stale` is the cleanup tool. Walks every favorite, identifies the stale ones (target FQCN not in canonical_index AND not reachable via alias chain), prompts the user per-entry to remap (auto-suggested when an unambiguous short-name match exists), drop, or skip.

Non-TTY invocations print the stale list to stderr and exit 1, instructing the user to re-run interactively. Equivalent to a `--check` / read-only mode without adding a second flag.

## Section 2: Edge cases

### 2.1 Alias-target favorite is NOT stale (two-segment form)

- [ ] **Background:** Real virtual-kit alias keys are two-segment `<vk>:<short>` (e.g., `claude:cleanup`), NOT the fully-qualified `<agg>:<vk>:<short>` dispatch form. The qualified form is resolved at dispatch time but isn't a key in `alias_index`, so favorites using it ARE considered stale (covered in 2.1b below). For "alias-target favorite is NOT stale", use the two-segment alias key.
- [ ] **Steps:** Pick a virtual-kit alias key from `dz list --show alias`. The key is the form printed (e.g., `claude:cleanup`).
  ```
  dz kit favorite cleanup claude:cleanup
  dz kit favorite --migrate-stale
  ```
- [ ] **Expected:** "No stale favorites" — the favorite resolves through the alias chain to a canonical.
- [ ] **Skip if:** no virtual kits exist in the current config (`dz list --show alias` is empty).

### 2.1b Qualified-alias-form favorite IS stale

- [ ] **Background:** A favorite using the fully-qualified dispatch form (`dazzletools:claude:cleanup`) IS flagged stale because that string isn't a key in `alias_index`. The suggestion in the migration prompt typically points at the canonical (`dazzletools:claude-cleanup`), which is the correct migration target.
- [ ] **Steps** (at favorite-set time, dazzlecmd warns this is a stale-target FQCN; we're verifying that warning + the migrate-stale detection are consistent):
  ```
  dz kit favorite cleanup dazzletools:claude:cleanup
  dz kit favorite --migrate-stale
  ```
- [ ] **Expected at set-time:** stderr warning "Warning: target FQCN ... not found in the current discovery. Favorite saved but may be stale." Exit 0 (saves anyway).
- [ ] **Expected at migrate-stale:** stderr lists the entry as stale; suggestion (if any) points at the canonical FQCN. Exit 1 (non-TTY) or interactive prompt (TTY).

### 2.2 Mixing positional args with --migrate-stale flag is rejected

- [ ] **Steps:** `dz kit favorite foo core:foo --migrate-stale`
- [ ] **Expected:** Error message: `--migrate-stale takes no positional arguments`. Exit 1. Config unchanged.

### 2.3 No args and no flag is rejected

- [ ] **Steps:** `dz kit favorite`
- [ ] **Expected:** Error message: `requires <short> <fqcn> positional args, or use --migrate-stale`. Exit 1.

### 2.4 EOF at prompt is treated as skip

- [ ] **Steps** (close stdin during prompt — Ctrl-D on POSIX, Ctrl-Z + Enter on Windows):
  ```
  [System.IO.File]::WriteAllText($env:DAZZLECMD_CONFIG, '{"favorites": {"x": "old:gone"}}')
  dz kit favorite --migrate-stale
  ```
  Press Ctrl-Z (Windows) or Ctrl-D (POSIX) at the prompt.
- [ ] **Expected:** Treated as skip (config unchanged, summary mentions 1 skipped).
