# Human Test Checklist: v0.7.44 -- Tier 2A.2 -- multi-language scaffolding templates

**Target version:** v0.7.44
**Ships with commit:** TBD
**Companion automated tests:** `tests/test_cmd_new_tool_languages.py` (20 new tests) + `tests/test_cmd_new_tool.py` (28 tests, 2 repurposed from the v0.7.40 guard). Total suite: 1096 passed, 14 skipped.

## What this is

v0.7.40 (Tier 2A.1) introduced `dz new <type> <name>` and the `--language` flag, but enforced a python-only guard pending the per-language scaffolding work. v0.7.44 (Tier 2A.2, items 4b-T3 + 4d-3) ships the per-language templates and removes the guard. Seven languages are now usable: `python` (full depth -- starter project including README and pytest stub via `--full`), `rust` (`Cargo.toml` + `src/main.rs`), `node` (`package.json` + `index.js`), `powershell` (`<name>.ps1`), `c_cpp` (`Makefile` + `main.c`), `docker` (`Dockerfile`), and `generic` (manifest + README explaining the runtime block, for tools that already exist as a binary or script).

The CLI rewrite uses a generic template-tree copy with placeholder substitution applied to both file contents AND filenames. Adding future languages is purely additive (drop in a new template directory).

2. dazzlecmd-lib installed in editable mode (`pip install -e packages/dazzlecmd-lib`)
3. Scratch directory you don't mind cluttering (or use the `$env:TEMP` / `/tmp` patterns below; the checklist cleans up after itself with `dz safedel`)

For each section, run with isolated config to avoid affecting your real `~/.dazzlecmd/config.json`:

- [ ] **Steps**:

- [ ] **Steps**: `dz new tool --language brainfuck foo` (or any name not in the seven supported)

### HV.6 -- Existing tool registration via `--kit` works for non-Python languages

- [ ] **Steps**:

- [ ] **Why this matters:** v0.7.40's `_register_in_kit` is language-agnostic; this confirms the rewrite preserves that.

## Section 3: Placeholder substitution edge cases

### 3.1 Hyphenated names use `name_underscore` correctly

- [ ] **Steps**: `dz new tool foo-bar-baz`
- [ ] **Expected file**: `foo_bar_baz.py` (underscored) -- NOT `foo-bar-baz.py`.
- [ ] **Manifest script_path**: `"foo_bar_baz.py"` -- consistent with the file.
- [ ] **Why this matters:** Python module names can't contain hyphens. The template filename `{name_underscore}.py.tmpl` does this transparently.

### 3.2 PowerShell preserves hyphens in script names

- [ ] **Steps**: `dz new tool --language powershell my-script`
- [ ] **Expected file**: `my-script.ps1` (hyphens preserved -- PowerShell allows them in filenames).

### 3.3 Description placeholder appears in non-manifest files

- [ ] **Steps**: `dz new tool --language rust --description "My specific tool" desctest`
- [ ] **Check**: both `.dazzlecmd.json` AND `Cargo.toml` reference "My specific tool".
- [ ] **Why this matters:** Confirms placeholder substitution runs on ALL template files, not just manifests.

## Section 4: Discovery and dispatch

### 4.1 Scaffolded Python tool is dispatchable

- [ ] **Steps**:
  ```
  dz new tool dispatchtest --kit dazzletools
  dz dispatchtest
  ```
- [ ] **Expected**: `dispatchtest: not yet implemented` plus `Arguments: []` (or similar). Exit code 0.
- [ ] **Why this matters:** The scaffolded Python tool must dispatch correctly through dazzlecmd-lib's python runner.

### 4.2 Scaffolded non-Python tool appears in `dz list` after registration

- [ ] **Steps**:
  ```
  dz new tool --language rust listtest --kit dazzletools
  dz list | grep listtest      # POSIX
  dz list | findstr listtest   # cmd.exe
  dz list | Select-String listtest   # PowerShell
  ```
- [ ] **Expected**: One row containing `listtest` with the right description.

### 4.3 Generic tool needs the user to fill in the runtime

- [ ] **Steps**: `dz new tool --language generic gentest --kit dazzletools` then `dz gentest`
- [ ] **Expected**: dispatch fails because the manifest's `binary_path` points at a placeholder (`gentest`) that doesn't exist. The error should be specific enough that the user knows what to fix (e.g., "binary not found" rather than a stack trace).
