# Human Test Checklist: shim read-Mapping + `dz mode switch` crash fix

**Target version:** v0.8.2 (dazzlecmd) / v0.7.1 (dazzlecmd-lib)
**Ships with commit:** v0.8.2 -- DazzleEntity Phase 1, Stage 1
**Companion automated tests:** `test_entity.py::TestShimMapping` (7 tests) + `test_mode.py::test_cache_manifest_accepts_entity` (1 test). Full suite: 1249 passed / 14 skipped.

## What this is

Phase 0 shipped the `DazzleEntity` shim with only `__getitem__`/`__setitem__`/`get`/`__contains__`. That left a hole: any code treating an entity as a full mapping (`.items()`/`.keys()`/`.values()`) crashed. The hole was load-bearing — `mode.cache_manifest()` does `{k: v for k, v in manifest.items() ...}`, and for any *discovered* tool `manifest` is an entity, so **`dz mode switch <tool>` → publish crashed with `AttributeError`**. The byte-identical gate covered `dz mode status` but never `dz mode switch`, and the `cache_manifest` tests only ever passed dict literals — so it was invisible. This stage completes the shim into a faithful read-Mapping (warned, so the Phase 1 ratchet still flags it) and adds the missing real-object regression test.

### HV.2 -- the shim is now a faithful read-Mapping

- [ ] **Steps:**
  ```
  python -c "from dazzlecmd_lib.entity import Tool; t=Tool.model_validate({'name':'rn','namespace':'core','runtime':{'type':'python'},'script':'rn.py'}); t['_fqcn']='core:rn'; print('items ok:', dict(t.items())['script']=='rn.py'); print('keys==values len:', len(list(t.keys()))==len(list(t.values()))); print('_fqcn present (cache_manifest filters it):', '_fqcn' in dict(t.items()))"
  ```
- [ ] **Expected:** all three print `True`.
- [ ] **Why:** `.items()/.keys()/.values()` were the missing methods; they must cover declared fields + extra (including computed `_`-keys).

### HV.3 -- the crash is fixed (the exact `cache_manifest` pattern on an entity)

- [ ] **Steps:**
  ```
  python -c "from dazzlecmd_lib.entity import Tool; t=Tool.model_validate({'name':'rn','namespace':'core'}); t['_fqcn']='core:rn'; clean={k:v for k,v in t.items() if not k.startswith('_')}; print('no crash; clean keys:', sorted(clean))"
  ```
- [ ] **Expected:** prints the clean key list (no `_fqcn`); **no `AttributeError`**.
- [ ] **Why:** this is literally what `mode.cache_manifest` runs; before this stage it raised `'Tool' object has no attribute 'items'`.

### HV.4 -- `dict(entity)` still works (pydantic contract preserved)

- [ ] **Steps:** `python -c "from dazzlecmd_lib.entity import Tool; print('name' in dict(Tool.model_validate({'name':'rn','namespace':'core'})))"`
- [ ] **Expected:** `True`. `__iter__`/`__len__` were intentionally NOT overridden.
- [ ] **Why:** overriding `__iter__` to yield keys would have broken `dict(entity)` and `model_copy` internals — this confirms we didn't.

### HV.5 -- read surfaces still byte-identical

- [ ] With an isolated `DAZZLECMD_CONFIG` (baseline state), `dz list` / `dz list --show all` / `dz mode status` match `tests/one-offs/baselines_v0.7.54/*.txt`; `dz tree` differs only on line 1 (`0.7.54` → `0.8.2`).
- [ ] **Why:** the shim addition must not perturb any rendered output.
