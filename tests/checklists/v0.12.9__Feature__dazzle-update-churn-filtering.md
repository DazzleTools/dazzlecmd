# Human Test Checklist: dz dazzle-update Churn Filtering

**Target version:** 0.12.9-alpha
**Ships with commit:** TBD (feature: hook-restamped version files reclassified from dirty to churn)
**Companion automated tests:** 13 in `dazzle-update/tests/test_churn.py`, 11 in `_repo_common/tests/test_repo_state.py::TestChurnPatterns` (real-git-repo fixtures), full repo suite 2264.

## What this is

Commit hooks that restamp version files (`__version__ = "X.Y.Z_branch_build-date-hash"`) made repos read DIRTY when nothing human-made changed. Modified files matching `churn_files` (defaults: `_version.py`, `version.py`) whose diff is a pure version restamp (at most two changed line-pairs, identical once version tokens are masked) now count as *churn*: excluded from dirty, disclosed via a NOTE line, `N churn` row bits, and a footer parenthetical. This checklist covers what the automated tests cannot: real hook interplay, live diff shapes, and the reading experience.

## Prerequisites

1. dazzlecmd installed editable; at least one repo on the machine using a version-stamping commit hook.
2. Nothing here writes anywhere; every command is a read-only scan. `--fix` appears only with `--dry-run`.

## High-Value Verification (~5 minutes)

### HV.1 -- A stamp-churned repo reads clean, disclosed

- [ ] **Steps:** pick a repo whose only change is the hook stamp (`git status` shows only the version file modified); run `dz dazzle-update --root <that repo> --no-fetch`
- [ ] **Expected:** NOT in DIRTY; footer says `1 repos clean and current (1 with only auto-stamp churn).`; a NOTE names the patterns.
- [ ] **Why this matters:** the entire feature -- if this fails, stamps still masquerade as work.

### HV.2 -- A real edit beside the stamp stays dirty

- [ ] **Steps:** in a scratch clone, modify the version file's stamp line AND another file; scan with `--root`.
- [ ] **Expected:** repo appears in DIRTY with both `N dirty` and `N churn` in its row bits.
- [ ] **Why this matters:** the failure mode this feature must never introduce is masking real work.

### HV.3 -- A manual version bump is work, not churn

- [ ] **Steps:** in a scratch clone of a repokit project, edit `MAJOR = 0` to `MAJOR = 1` in `_version.py` (do not touch the `__version__` line); scan.
- [ ] **Expected:** DIRTY, zero churn -- the changed line has no dotted version token.
- [ ] **Why this matters:** a human mid-bump reading "clean" would ship a half-done version change.

### HV.4 -- The audit agrees with the report

- [ ] **Steps:** `python tests/one-offs/thinking/churn_audit.py`
- [ ] **Expected:** every listed diff is visibly a version restamp; `0 audit/production mismatch(es)` in the summary.
- [ ] **Why this matters:** the audit is the human-verifiable ground truth for every reclassification.

### HV.5 -- Disabling the filter restores old behavior

- [ ] **Steps:** config with `{"churn_files": [], "churn_files_replace": true}`; scan the HV.1 repo with it.
- [ ] **Expected:** the repo is DIRTY again; no NOTE, no churn bits, plain footer.
- [ ] **Why this matters:** the escape hatch for machines whose version files are hand-maintained.

## Section 1: Disclosure surfaces (~5 min)

### 1.1 NOTE appears in fresh and cached runs
- [ ] **Steps:** full scan, then `--cached`; compare NOTE lines.
- [ ] **Expected:** both runs carry the churn NOTE with the same patterns. (Cached scans written before 0.12.9 have no churn data and correctly show no NOTE.)

### 1.2 Footer parenthetical only when churn-only repos exist
- [ ] **Steps:** scan a root with no stamped repos.
- [ ] **Expected:** plain `N repos clean and current.` -- no empty parenthetical.

### 1.3 --fix refuses over churn
- [ ] **Steps:** on a churn-only repo that is also behind: `--fix --dry-run`.
- [ ] **Expected:** refusal reading `auto-stamp churn present -- refusing to pull (will not stash)`.

## What the automated tests DO cover

Filename gating (nested paths, basenames, case), content verdicts (txt/JSON/Python restamps, logic edits, manual bumps, 3+ lines, staged stamps, deletions), config merge/replace, classification, all three disclosure surfaces, the --fix gate, and the dirty-refusal fall-through regression.

## What the automated tests DON'T cover

- Real hook interplay: the stamp your hooks write today matching the token regex
- The reading experience: whether DIRTY now contains only things worth reading
- Cross-machine conventions: stamp shapes on boxes not surveyed (aktuldjr)
- Performance feel of the per-candidate `git diff` calls on a full scan

## Reporting issues found

A misclassified file is the report to file: include `git status --porcelain` and `git diff HEAD -- <file>` for it, plus the audit script's row.

## Cleanup

Nothing to clean; all steps are read-only or in scratch clones you delete yourself (prefer `dz safedel`).
