## What this is

The B-arc rewired the entire verb-execution core: `states.py` now imports `continuum.py` (StateAxis HAS-A Continuum); a generic `TransitionContext` + `Receipt` replaced the per-verb logic, and `VisibilityContext`/`ContainmentContext`/`AliasRebindContext` were re-expressed over it (their `reversible`/`conserved` now trace to the declared registry edge); and `--cascade` (a general ContinuumSpace apply-mode) was added to `dz kit visibility`. **The whole arc is byte-identical on the existing CLI surface** — so this checklist's job is the REAL-SHELL gap the mocks + the (parked-drifted) byte-gate miss: confirm dispatch/visibility/config-writes still work end-to-end, and exercise the one genuinely new user-facing surface, `--cascade`.

## Prerequisites

1. Windows/POSIX with the repo installed (editable). Python 3.12.
2. **Isolated config** — never touch real dotfiles. Set `DAZZLECMD_CONFIG` to a throwaway path; delete it to reset.
   - **cmd.exe:** `set DAZZLECMD_CONFIG=%TEMP%\dz_b2c.json`
   - **PowerShell:** `$env:DAZZLECMD_CONFIG = "$env:TEMP\dz_b2c.json"`
   - **POSIX:** `export DAZZLECMD_CONFIG=/tmp/dz_b2c.json`
3. Reset between sections: delete that file (`del %DAZZLECMD_CONFIG%` / `Remove-Item $env:DAZZLECMD_CONFIG` / `rm -f "$DAZZLECMD_CONFIG"`).
4. `dz` ≡ `python -m dazzlecmd` below (use whichever resolves).

## High-Value Verification (~5 min)

### HV.1 — Dispatch still works (the core didn't break)

- [ ] `dz list` (renders the tool table) and `dz find --help` (a real tool dispatches + runs).
- [ ] **Expected:** the list renders; `find` runs its own `--help`. **Why:** the B-arc rewired the verb-execution core — if dispatch broke, everything is broken.

### HV.2 — Visibility rung path UNCHANGED (independent filters)

- [ ] `dz kit visibility hide find` then `dz kit visibility status find`.
- [ ] **Expected:** `Hidden: core:find`; status shows `presence: hidden`. The config has `core:find` in `hidden_tools` **only** (NOT `silenced_hints`) — hide leaves hints independent. **Why:** B2 must NOT have made the default `hide` monotone.

### HV.3 — `--cascade` (bare) = slice-to-0 (the new feature)

- [ ] reset config; `dz kit visibility hide find --cascade`.
- [ ] **Expected:** prints `Cascade suppress core:find: hidden (hide), silenced (silence)` / `set: hidden, silenced`; config has `core:find` in BOTH `hidden_tools` and `silenced_hints.tools`, NOT `shadowed_tools`. **Why:** the core cascade semantic (subsume current + weaker toward neutral).

### HV.4 — `--cascade` C3 (apply-rest-and-warn)

- [ ] reset; `dz kit visibility shadow safedel --cascade`.
- [ ] **Expected:** applies `silenced`+`hidden` to `core:safedel`, REFUSES the `shadowed` rung with a `constitutional ... C3` warning on stderr, exit 0; `core:safedel` NOT in `shadowed_tools`. **Why:** a constitutional tool may be hidden but never shadowed — even via a cascade slice.

### HV.5 — status navigator is frame-correct + C3-aware

- [ ] `dz kit visibility hide safedel` then `dz kit visibility status safedel`.
- [ ] **Expected:** `presence: hidden`; `less visible -> (none: ... constitutional -- 'shadow' refused by C3 ...)`; `more visible -> dz kit visibility unhide core:safedel`. **Why:** the navigator must not suggest the C3-refused shadow move.

### HV.6 — bare `dz kit` / `dz kit list` render

- [ ] `dz kit list` and bare `dz kit`.
- [ ] **Expected:** both render the kit table identically. **Why:** the kit-list renderer rides the refactored lib.

## Section 2: Visibility rung path (must be byte-identical to pre-B-arc)

- [ ] **2.1** silence/unsilence, hide/unhide, shadow/unshadow each toggle their OWN config key only (`silenced_hints.tools` / `hidden_tools` / `shadowed_tools`) — independent filters.
- [ ] **2.2** `dz kit visibility` (bare overview) lists tools at non-default rungs incl. hidden.
- [ ] **2.3** idempotency: repeating `hide find` says "already hidden".

## Section 3: `--cascade` (the new surface)

- [ ] **3.1** bare `--cascade` (HV.3) — slice-to-0.
- [ ] **3.2** `--cascade=down` — `dz kit visibility hide find --cascade=down` → sets `hidden` + `shadowed` (toward the cold pole), NOT `silenced`.
- [ ] **3.3** `--cascade=-1,0` (offset window) — from hidden = `{shadowed, hidden}`.
- [ ] **3.4** restore cascade — `dz kit visibility unhide find --cascade` clears the bundle it set.
- [ ] **3.5** bad spec — `dz kit visibility hide find --cascade=garbage,1,2` → `Error: bad --cascade value ...`, exit 1, nothing written.
- [ ] **3.6** the op PRINTS the affected rungs + their verbs before/with applying (transparency).

## Section 4: Lib primitives + the registry-sourced receipts (via python)

- [ ] **4.1** `python -c "from dazzlecmd_lib.groupable import KIT_PRESENCE_SPACE as s; print(s.cascade_to_neutral('visibility','hidden'))"` → `('hidden', 'silenced')`.
- [ ] **4.2** `... s.slice('visibility','hidden',lo=-1,hi=2)` → `('shadowed','hidden','silenced','visible')`.
- [ ] **4.3** entity-verb receipts trace to the registry: a `VisibilityContext`/`ContainmentContext`/`AliasRebindContext` apply returns a receipt whose `reversible`/conserved-name match the declared edge in `build_default_registry()` (the automated trace tests cover this; spot-check via python if desired).
