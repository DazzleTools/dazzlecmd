# Human Test Checklist: redact-msinfo (dazzletools)

**Target version:** 0.10.2
**Ships with commit:** v0.10.2 (the `windows` tools release; tool designed in the v0.7.54 batch)
**Companion automated tests:** 40 tests in `projects/dazzletools/redact-msinfo/tests/test_redact_msinfo.py` (section resolution, PII scrubbing, runtime hostname scrub, render keep/strip, self-verify pass/fail, end-to-end `main()` dispatch)

## What this is

`dz redact-msinfo` takes a Windows **msinfo32** text export (UTF-16 LE, full of hardware IDs, serials, network addresses, user names, and a near-complete software inventory) and produces a UTF-8, ASCII-safe redaction suitable for sharing. It keeps a small default set of sections verbatim, strips the rest to one-line placeholders, scrubs PII inside kept sections, and runs a self-verification pass. `--include` / `--exclude` let you override which sections are kept.

This document is what a human runs to confirm the tool behaves correctly end-to-end — things the mocks can't see: real UTF-16 decoding, terminal rendering of the report, the interactive feel of `--list-sections`, and the honesty of the `[WARN]` / verify safety net when you pull in a risky section.

## Prerequisites

1. **Environment:** dazzlecmd installed so `dz` is on PATH; Python 3.x. Works on Windows, Linux, macOS (the tool is pure-stdlib and the input is just a text file).
2. **Fixture:** a synthetic msinfo export ships at
   `projects/dazzletools/redact-msinfo/tests/fixtures/sample_msinfo.txt`
   (UTF-16 LE, all identifiers obviously fake: `TESTHOST01`, `192.168.x`, `sk-test-EXAMPLE...`). Regenerate it any time with
   `python projects/dazzletools/redact-msinfo/tests/fixtures/make_sample.py`.
3. **Hostname note (important):** the fixture's dummy hostname is `TESTHOST01`. The tool auto-detects *your* machine's hostname for the bare-hostname scrub + verify, so when testing **against the fixture** always pass `--hostname TESTHOST01`. Against a real export from your own machine, omit `--hostname` and let it auto-detect.
4. **State isolation:** always write output to a throwaway temp path (see per-shell setup below). The tool **never** modifies its input and refuses to write output over the input path. Delete temp outputs when done — included-section outputs can contain residual secrets.

**Per-shell scratch setup** (run once; `$F` / `%F%` = fixture, `$T` / `%T%` = temp out dir):

**cmd.exe**:
```cmd
set F=projects\dazzletools\redact-msinfo\tests\fixtures\sample_msinfo.txt
set T=%TEMP%\rm_ck
mkdir %T%
```

**PowerShell**:
```powershell
$F = "projects\dazzletools\redact-msinfo\tests\fixtures\sample_msinfo.txt"
$T = "$env:TEMP\rm_ck"; New-Item -ItemType Directory -Force $T | Out-Null
```

**POSIX**:
```bash
F=projects/dazzletools/redact-msinfo/tests/fixtures/sample_msinfo.txt
T=$TMPDIR/rm_ck; mkdir -p "$T"
```

**Reset between sections:** each test writes its own output file; no shared state. To start clean, delete `%T%` / `$T` and recreate it. **Cleanup at the end** is in the final section.

## High-Value Verification (~5 minutes)

If you only have 5 minutes, run these. If any fail, the tool is broken.

### HV.1 — Tool is discovered and dispatches

Validates: kit registration + Python entry-point wiring.

- [ ] **Steps** (same across shells, `dz` only):
  ```
  dz list
  dz redact-msinfo --list-sections
  ```
- [ ] **Expected:** `redact-msinfo` appears under the `dazzletools:` section of `dz list`; `--list-sections` prints "Default-KEPT sections" (3) and "Default-STRIPPED sections" (many) then exits 0.
- [ ] **Why this matters:** if the kit registration is missing, the tool is silently invisible (`dz` filters tools by the kit's `tools` list).

### HV.2 — Default redaction passes self-verify

Validates: UTF-16 read, section strip, PII scrub, verify.

- [ ] **Steps** (POSIX shown; use the scratch vars from Prerequisites):
  ```bash
  dz redact-msinfo --input "$F" --output "$T/default.txt" --hostname TESTHOST01
  ```
- [ ] **Expected:** ends with `[OK   ] All verification checks passed.` and exit 0. `[INFO ] Kept sections` lists `[Display] [Problem Devices] [System Summary]`.
- [ ] **Why this matters:** this is the whole point of the tool — a clean export with verification.

### HV.3 — PII is actually gone from the output

Validates: the scrub really removed identifiers (not just claimed to).

- [ ] **Steps** (view the file; pick your shell):

  **cmd.exe**: `findstr /C:"REDACTED" %T%\default.txt` then `findstr /C:"TESTHOST01" %T%\default.txt`
  **PowerShell**: `Select-String REDACTED $T\default.txt; Select-String TESTHOST01 $T\default.txt`
  **POSIX**: `grep REDACTED "$T/default.txt"; grep -c TESTHOST01 "$T/default.txt"`
- [ ] **Expected:** many `[REDACTED-*]` tokens present; **zero** matches for `TESTHOST01`, `00:11:22:33:44:55` (MAC), `192.168.1.50` (IP), `SN-TEST-123456` (serial).
- [ ] **Why this matters:** a redactor that leaves PII is worse than useless — it gives false confidence.

### HV.4 — `--include` / `--exclude` change the kept set

Validates: section selection, the headline feature.

- [ ] **Steps:**
  ```bash
  dz redact-msinfo --input "$F" --output "$T/inc.txt" --hostname TESTHOST01 --include SystemDrivers
  dz redact-msinfo --input "$F" --output "$T/exc.txt" --hostname TESTHOST01 --exclude Display
  ```
- [ ] **Expected:** the include run keeps `[System Drivers]` (its `testdrv.sys` row appears) and prints a `[WARN ]`; the exclude run replaces `[Display]` with `[Display]  -- REMOVED (...)`.
- [ ] **Why this matters:** this is the feature this commit adds.

### HV.5 — Force-including a risky section WARNs and the secret survives

Validates: the safety net is honest about its limits.

- [ ] **Steps:**
  ```bash
  dz redact-msinfo --input "$F" --output "$T/env.txt" --hostname TESTHOST01 --include EnvironmentVariables
  grep -c "sk-test-EXAMPLE" "$T/env.txt"     # POSIX; see HV.3 for cmd/PowerShell equivalents
  ```
- [ ] **Expected:** a 4-line `[WARN ]` about included sections; verify prints `[FAIL ]` (the env-var "User Name" column trips the check); the fake secret `sk-test-EXAMPLE-NOT-A-REAL-KEY-000` is **still present** in the output (count = 1).
- [ ] **Why this matters:** the scrubber cannot catch arbitrary secrets in arbitrary sections — the WARN + verify-FAIL is how the user is told to review before sharing. If this silently "passed", a user could leak a real key.

### HV.6 — Bad input is rejected, not silently mishandled

Validates: error handling / exit codes.

- [ ] **Steps:**
  ```bash
  dz redact-msinfo --input "$F" --hostname TESTHOST01 --include Display --exclude Display --output "$T/x.txt"; echo "exit=$?"
  dz redact-msinfo --input "$F" --hostname TESTHOST01 --include Bogus --output "$T/y.txt"; echo "exit=$?"
  ```
- [ ] **Expected:** both print a clear `[ERROR]` and exit `1`; no output file is written.
- [ ] **Why this matters:** a typo'd `--exclude` that silently no-ops could leave a section you wanted stripped in the output.

After HV passes you have high confidence the tool shipped correctly. Detailed sections below cover the report layout, name-matching flexibility, the self-verify internals, and cross-platform/rendering concerns.

## Section 1: Output layout & rendering

### 1.1 System Summary is reordered

- [ ] **Steps:** view `$T/default.txt`.
- [ ] **Expected:** under `[System Summary]` the rows are grouped under `--- OS Identity ---`, `--- Hardware Identity ---`, `--- Other System Information ---`, in that order. `OS Name` / `Version` appear in the OS Identity group.
- [ ] **Check:** no `--- Insider ... ---` or other machine-specific wording (the tool was genericized).

### 1.2 Stripped sections are one-line placeholders with reasons

- [ ] **Expected:** each stripped section is a single line like
  `[System Drivers]  -- REMOVED (loaded kernel driver list -- exposes installed software footprint)`.
- [ ] **Check:** no body rows from stripped sections leak through.

### 1.3 Output is ASCII-only (Windows codepage safe)

- [ ] **Steps** (any shell with Python):
  ```
  python -c "import sys;d=open(sys.argv[1],encoding='utf-8').read();print('non-ascii:',sum(1 for c in d if ord(c)>127))" %T%\default.txt
  ```
  (POSIX: use `"$T/default.txt"`.)
- [ ] **Expected:** `non-ascii: 0`. Eyeball the file in your terminal — no mojibake, no smart quotes, no stray boxes.
- [ ] **Why:** msinfo exports carry invisible Unicode direction marks; output must be safe on cmd codepage 437/1252.

## Section 2: Section-name matching

### 2.1 Names match loosely (case / spaces / brackets ignored)

- [ ] **Steps:** run the include against the same section three ways:
  ```bash
  dz redact-msinfo --input "$F" --output "$T/n1.txt" --hostname TESTHOST01 --include "System Drivers"
  dz redact-msinfo --input "$F" --output "$T/n2.txt" --hostname TESTHOST01 --include "systemdrivers"
  dz redact-msinfo --input "$F" --output "$T/n3.txt" --hostname TESTHOST01 --include "[System Drivers]"
  ```
- [ ] **Expected:** all three keep `[System Drivers]` identically (each prints the WARN).

### 2.2 Comma lists and repeated flags both work

- [ ] **Steps:**
  ```bash
  dz redact-msinfo --input "$F" --output "$T/m.txt" --hostname TESTHOST01 --include "SystemDrivers,Services" --include Drives
  ```
- [ ] **Expected:** `[INFO ] Kept sections` includes `[System Drivers]`, `[Services]`, `[Drives]` plus the defaults.

### 2.3 `--list-sections` reads well

- [ ] **Steps:** `dz redact-msinfo --list-sections`
- [ ] **Expected:** KEEP block then STRIP block (each STRIP line followed by an indented reason), ending with usage examples. Columns line up; readable at 80 cols.

## Section 3: Self-verify behavior

### 3.1 Verify re-checks the written file independently

- [ ] **Expected (default run):** verify reports `[OK ]` for OS Name, Version, hostname, MAC, IP fields, volume serials, User Name.

### 3.2 Verify can fail (conservative bias)

- [ ] **Steps:** the `--include EnvironmentVariables` run from HV.5.
- [ ] **Expected:** `[FAIL ]` appears and the process exits 1. A FAIL means "do not share until reviewed", not necessarily a tool bug — it errs toward failing.

### 3.3 `--no-verify` skips the pass

- [ ] **Steps:** `dz redact-msinfo --input "$F" --output "$T/nv.txt" --hostname TESTHOST01 --no-verify`
- [ ] **Expected:** no `[VERIFY]` block; exit 0; output still written and redacted.

## Section 4: Safety / I-O guards

### 4.1 Input is never modified; same-path write refused

- [ ] **Steps:** point `--output` at the input path.
- [ ] **Expected:** `[ERROR] Input and output are the same file` and exit 1; the input is untouched.

### 4.2 Missing / nonexistent input

- [ ] **Steps:** run with no `--input`; then with `--input does-not-exist.txt`.
- [ ] **Expected:** `--input is required` (exit 2) and `Input file not found` (exit 1) respectively.

### 4.3 Default output is a sidecar

- [ ] **Steps:** run with `--input "$F"` and **no** `--output`.
- [ ] **Expected:** writes `sample_msinfo.redacted.txt` next to the fixture (not over the input). *Delete it afterward.*

## What the automated tests DON'T cover

- **Terminal rendering** of the report and `--list-sections` (column alignment, 80-col wrap, codepage 437/1252 on real cmd.exe).
- **Real msinfo32 exports** — the fixture is synthetic; only a real export exercises the full section zoo and odd row formats. (Test against your own export with auto-detected hostname.)
- **UTF-16 variants** — the fixture is LE-with-BOM; a real-world BE or BOM-less file would only be caught by hand.
- **Cross-platform** — the tests run on one OS; the checklist gets run on all.
- **Error-message clarity / discoverability** — does a new user find `--list-sections` and understand the WARN?
- **Performance feel** on a large (10k+ line) export.

## Reporting issues found

1. Note the section/step number (e.g., HV.5, 1.3).
2. Capture the exact command and output.
3. Save the offending output file (scrub any real secrets first).
4. File an issue referencing this checklist (`v0.10.2__Tool__redact-msinfo-section-selection.md`) and the shipping commit.
