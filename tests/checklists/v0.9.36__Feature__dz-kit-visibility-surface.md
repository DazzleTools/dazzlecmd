# Human Test Checklist: `dz kit visibility` surface + presence navigator

**Target version:** v0.9.36
**Ships with commit:** "v0.9.36 feat(cli): dz kit visibility surface + KIT_PRESENCE_SPACE navigator + C3"
**Companion automated tests:** `tests/test_cli_kit.py` (TestKitShadow incl. C3, TestKitVisibilityList, TestKitVisibilityStatus); `packages/dazzlecmd-lib/tests/test_continuum.py` (ContinuumSpace). Full suite 1488 passed / 14 skipped.

## What this is

The visibility toggles (`silence/hide/shadow` + inverses) moved under a new `dz kit visibility` subcommand, with a `status` navigator (current presence level + the next stronger/weaker move) backed by `KIT_PRESENCE_SPACE`. `dz kit shadow` now refuses constitutional tools (C3). This checklist covers what the mocks can't: real argparse parsing, the moved-verb surface change, shell rendering, and the C3 refusal against a real discovered tool.

## Prerequisites

Use an isolated config so you never touch your real dotfiles:

- **cmd.exe:** `set DAZZLECMD_CONFIG=%TEMP%\dzvis.json`
- **PowerShell:** `$env:DAZZLECMD_CONFIG = "$env:TEMP\dzvis.json"`
- **POSIX:** `export DAZZLECMD_CONFIG=/tmp/dzvis.json`

Reset between sections: delete that file (`del`/`Remove-Item`/`rm -f`).

## High-Value Verification (~5 min)

### HV.1 -- The top level is de-cluttered
- [ ] `dz kit -h`
- [ ] **Expected:** the subcommand list shows `visibility` (not `silence`/`hide`/`shadow`/`silenced`); ~10 entries, not 16.
- [ ] **Why this matters:** the headline UX win -- the hodge-podge is gone.

### HV.2 -- The nested verbs exist and work
- [ ] `dz kit visibility -h` -> lists silence/unsilence/hide/unhide/shadow/unshadow/status.
- [ ] `dz kit visibility hide a:b:tool` -> "Hidden: a:b:tool".
- [ ] **Expected:** the verb runs; config gains `hidden_tools: ["a:b:tool"]`.
- [ ] **Why this matters:** the moved verbs must still function from their new home.

### HV.3 -- The navigator shows both neighbors (in the surface's frame)
- [ ] (after HV.2) `dz kit visibility status a:b:tool`
- [ ] **Expected:** `presence: hidden`; `less visible -> dz kit visibility shadow a:b:tool`; `more visible -> dz kit visibility unhide a:b:tool`. (Labels are "less/more visible" -- the surface's own frame -- not "stronger/weaker".)
- [ ] **Why this matters:** the both-neighbors navigator is the new affordance, and its labels must read correctly in English for the "visibility" frame.

### HV.4 -- C3 refuses shadowing a constitutional tool
- [ ] `dz kit visibility shadow core:safedel`
- [ ] **Expected:** "Refused: core:safedel is constitutional -- it may be hidden but never shadowed ..."; exit code 1; config `shadowed_tools` does NOT contain it.
- [ ] **Why this matters:** prevents removing a lib primitive dz depends on.

### HV.5 -- The overview includes the hidden rung
- [ ] (after HV.2) `dz kit visibility`
- [ ] **Expected:** three rungs (silenced / hidden / shadowed); `a:b:tool` appears under **hidden** (the old `silenced` query omitted hidden).
- [ ] **Why this matters:** the overview is now complete across all three presence channels.

## Section 1: Behavior + idempotency

### 1.1 Round-trip each rung
- [ ] `silence` then `unsilence`; `hide` then `unhide`; `shadow` then `unshadow` (on a non-constitutional FQCN like `a:b:tool`).
- [ ] **Check:** each toggle adds then removes the entry in the matching config key; idempotent (running twice doesn't duplicate).

### 1.2 status at the poles
- [ ] `status` on a fully-visible tool -> `stronger -> ... silence`, `weaker -> (already fully present: visible)`.
- [ ] `shadow a:b:tool` then `status a:b:tool` -> `presence: shadowed`, `stronger -> (already strongest: shadowed)`, `weaker -> ... unshadow`.

### 1.3 Old top-level verbs are gone
- [ ] `dz kit silence a:b:tool` -> argparse error (invalid choice). Confirms the clean move (no stale top-level verb).

## What the automated tests DON'T cover

- The C3 refusal against a *really discovered* constitutional tool (the unit test stubs the project; here it's resolved from real discovery).
- Exit codes in a real shell.
