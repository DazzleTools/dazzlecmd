# Human Test Checklist: v0.7.36 — Tier 1B — `dz kit list <kit>` column parity (closes #48)

**Target version:** v0.7.36 **Ships with commit:** TBD (Tier 1 commit 8) **Companion automated tests:** `tests/test_cli_kit.py::TestKitListDrillInColumnWidths` (5 tests). Total suite: 979 passed, 13 skipped.

## What this is

v0.7.36 fixes a long-standing rendering inconsistency in the `dz kit list <kit>` canonical-kit drill-in. The drill-in had retained pre-v0.7.27 fixed-width columns (16 chars for name, 16 for platform) and a hardcoded 55-character description truncation. Result: longer names like `claude-session-metadata` collided with the platform column, and descriptions got chopped even when the terminal had plenty of room.

The fix: compute column widths from actual data, use `_wrap_description` for terminal-aware wrapping. The virtual-kit drill-in path (which already does this correctly via `_render_virtual_kit_aliases`) is untouched.

## Prerequisites

1. dazzlecmd installed in editable mode (`pip install -e .`)
2. A multi-tool kit in the discovered set (e.g., `dazzletools` ships with many tools including `claude-session-metadata` which has a 24-char short name — longer than the old 16-char fixed column).

## High-Value Verification (~3 minutes)

### HV.1 — Long-name kit renders without column collision

- [ ] **Steps:** `dz kit list dazzletools` (or any kit with at least one tool whose name exceeds 16 chars)
- [ ] **Expected:** Names align in a single left-justified column whose width matches the longest name in the kit. The platform column starts after the longest name + a gap. Descriptions wrap to terminal width if they exceed the available description column.
- [ ] **Specifically check:** `claude-session-metadata cross-platform` (or similar long-name row) has at least 2 spaces between the name and `cross-platform` — no collision.

### HV.2 — Descriptions wrap, don't truncate

- [ ] **Steps:** Find a tool with a long description (e.g., `dz info <some-tool>` to see, then look in `dz kit list <its-kit>`).
- [ ] **Expected:** Description text wraps to multiple lines when needed. The continuation lines align with the description column start. No `...` ellipsis truncation (unless the description itself contains `...`).

### HV.3 — Short-name kit still renders correctly

- [ ] **Steps:** Pick a kit where all tool names are short (e.g., the `core` kit usually has short names).
- [ ] **Expected:** Identical visual layout as before — name + platform + description, just with widths fit to the actual data. No regression for the common case.

### HV.4 — Virtual-kit drill-in unaffected

- [ ] **Steps:** `dz kit list claude` (or any virtual kit in your config)
- [ ] **Expected:** Output identical to v0.7.35. The virtual-kit branch uses `_render_virtual_kit_aliases` which already had correct column-width logic; this commit doesn't touch it.

### HV.5 — pytest baseline green

- [ ] **Steps:** `python -m pytest tests/test_cli_kit.py -q`
- [ ] **Expected:** `45 passed` (40 previous + 5 new).

## Section 1: Rendering edge cases

### 1.1 Kit with only one short-named tool

- [ ] **Steps:** Find a kit with exactly one short-named tool, or fabricate one via a test config.
- [ ] **Expected:** Name column fits the one short name; platform column fits the one platform string; description wraps if needed. No misalignment.

### 1.2 Kit with only one long-named tool

- [ ] **Steps:** Find or construct a kit with one long-named tool.
- [ ] **Expected:** Name column expands to fit the long name; platform column starts after a 2-space gap. Single row renders cleanly.

### 1.3 Tool ref in kit manifest that doesn't match a project

- [ ] **Steps:** Find or construct a kit whose `tools` manifest entry references a nonexistent tool (e.g., a kit imported but its target tool deleted).
- [ ] **Expected:** Row renders with the tool name + empty platform + `(not found)` as the description. The `(not found)` marker is preserved from v0.7.35.

---

## Section 2: Cross-shell verification

### 2.1 cmd.exe

- [ ] **Steps (cmd.exe)**: `dz kit list dazzletools`
- [ ] **Expected:** Layout identical to PowerShell. ASCII alignment characters render correctly (no mojibake).

### 2.2 PowerShell

- [ ] **Steps (PowerShell)**: `dz kit list dazzletools`
- [ ] **Expected:** Layout identical to cmd.exe.

### 2.3 Narrow terminal width (resize to ~60 columns)

- [ ] **Steps:** Resize the terminal to ~60 columns wide, then `dz kit list dazzletools`.
- [ ] **Expected:** Descriptions wrap aggressively to fit the narrow width. Name + platform columns still align.

### 2.4 Wide terminal (200+ columns)

- [ ] **Steps:** Resize the terminal to 200+ columns, then `dz kit list dazzletools`.
- [ ] **Expected:** Most descriptions fit on a single line. Wrapping only happens for the longest descriptions.
