# Human Test Checklist -- `safe-icacls` (alias `sicacls`)

**Tool:** `dz safe-icacls` / `dz sicacls` (canonical FQCN `dazzletools:safe-icacls`)
**Virtual kit:** `windows` (`dazzletools:windows:sicacls`)
**Type:** New tool -- loop-safe passthrough wrapper around Windows `icacls`
**Platform:** Windows only (`icacls` ships in `System32`)

> **Run these in PowerShell or cmd, NOT Git Bash/WSL.** Git Bash's MSYS layer
> rewrites `/grant`, `/T`, etc. into fake Windows paths (e.g. `/grant` ->
> `C:\Program Files\Git\grant`). That is a shell artifact, not a tool bug --
> but it makes every `icacls`-style argument unusable from Bash. The tool is
> meant to be driven from an elevated PowerShell/cmd prompt.

---

## What the automated tests already cover (don't re-do by hand)

- Wrapper-flag vs icacls-arg splitting; `--safe-progress` value parsing.
- `split_path_and_ops` (path is token 0; `/T` stripped; ops preserved).
- `main()` routing: no `/T` -> passthrough; `/T` -> safe walk; `--unsafe` ->
  passthrough; `/save|/restore` -> passthrough + warning; help / no-args.
- **Real junction pruning** (Windows): builds a self-referential junction and
  asserts every object is visited once, the junction gets `/L` and is NOT
  descended, plus `--safe-skip-reparse` and `--safe-dirs-only` behavior.

Run them: `python -m pytest projects/dazzletools/safe-icacls/tests -q`

## What ONLY a human can confirm (the point of this checklist)

Mocks stub out `icacls`, so they never prove the ACL actually changed, never
exercise a real elevated token, never hit the legacy `Everyone:Deny`
compatibility junctions, and never show you the real console output. Do that
below.

## Prerequisites

- [ ] An **elevated** PowerShell ("Run as administrator").
- [ ] `dz` resolves (`dz version` prints a version).
- [ ] A scratch directory you don't care about. The steps build one.

## Section 1 -- Discovery & wiring

- [ ] `dz list` shows `safe-icacls [+]` under `dazzletools:` and a
      `dazzletools:windows:` group containing `sicacls` and `redact-msinfo`.
- [ ] `dz kit` lists `windows   2 tool(s)  [always active]`.
- [ ] `dz safe-icacls -h` prints the "WHY THIS EXISTS" help.
- [ ] `dz sicacls -h` prints the **same** help (alias resolves).
- [ ] `dz safe-icacls` with no args prints help (exit 0), does nothing.

## Section 2 -- Build a looping scratch tree

```powershell
$t = "$env:TEMP\sicacls-check"
Remove-Item $t -Recurse -Force -ErrorAction SilentlyContinue
New-Item -ItemType Directory $t\sub1 -Force | Out-Null
New-Item -ItemType Directory $t\sub2 -Force | Out-Null
"x" | Set-Content $t\file1.txt
"y" | Set-Content $t\sub1\file2.txt
New-Item -ItemType Junction -Path $t\loop -Target $t | Out-Null   # self-referential
```

- [ ] `Get-ChildItem $t -Force` shows `loop` plus the two subdirs and file.

## Section 3 -- Loop safety (the core guarantee)

- [ ] **Dry run:**
      `dz safe-icacls $t /grant "Everyone:(OI)(CI)R" /T /C --safe-dry-run --safe-verbose`
  - [ ] Lists each object **once**: 3 dirs, 2 files, `loop` as `[LINK]`.
  - [ ] The `[LINK]` line for `loop` shows `/L` appended.
  - [ ] It **terminates** (does not print `loop\loop\loop...`). Exit 0.
  - [ ] Per-object commands have **no** `/T` (we drive recursion).
- [ ] **Sanity check that native would hang** (optional, Ctrl-C after a beat):
      `icacls $t /grant "Everyone:(OI)(CI)R" /T /C` -- watch it start walking
      `...\loop\loop\loop\...`. **Ctrl-C to stop it.** (Skip if you'd rather not.)
- [ ] **Real run:** drop `--safe-dry-run`:
      `dz safe-icacls $t /grant "Everyone:(OI)(CI)R" /T /C`
  - [ ] Prints `safe-icacls processed: dirs=3 files=2 reparse=1`. Exit 0.
  - [ ] `icacls $t` shows `Everyone:(OI)(CI)(R)`.
  - [ ] `icacls $t\sub1\file2.txt` shows `Everyone:...(R)` (inherited or explicit).

## Section 4 -- Passthrough transparency (no `/T`)

- [ ] `dz safe-icacls $t\file1.txt /grant "Everyone:(R)"` runs native icacls
      and prints `Successfully processed 1 files`. Exit 0.
- [ ] `dz safe-icacls $t` (just a path, no op) behaves like bare `icacls $t`
      (prints the ACL). Exit 0.
- [ ] An intentionally bad arg, e.g. `dz safe-icacls $t /bogus`, surfaces
      icacls's own error and a non-zero exit (passthrough is transparent).

## Section 5 -- Flags & escape hatches

- [ ] `--safe-dirs-only`: re-run the Section 3 real command with this flag;
      summary shows `files=0`; the grant still works via `(OI)(CI)` inheritance.
- [ ] `--safe-skip-reparse`: summary shows `reparse=0`; `loop` is untouched.
- [ ] `--unsafe` with `/T`: prints a warning that native recursion may loop,
      then hands off to native icacls. (On the junction tree this WILL loop --
      Ctrl-C. Demonstrates the escape hatch is honestly labeled.)
- [ ] `/save` with `/T`: `dz safe-icacls $t /save acl.bak /T` prints the
      "cannot be decomposed safely" warning and passes through.

## Section 6 -- The real-world scenario (optional, destructive-ish)

Only if you have a profile/folder that actually fails with native icacls:

- [ ] On a folder with legacy junctions (e.g. a `C:\Users\<user>` profile),
      `dz safe-icacls "C:\Users\<user>" /grant Administrators:(OI)(CI)F /T /C`
      completes instead of looping, and reports a handful of
      `reparse-skipped(denied)` for the `Everyone:Deny` compatibility
      junctions (expected -- those hold no data).

## Cleanup

```powershell
# Remove the junction WITHOUT following it into the target, then the tree.
[System.IO.Directory]::Delete("$env:TEMP\sicacls-check\loop", $false)
Remove-Item "$env:TEMP\sicacls-check" -Recurse -Force
```

- [ ] `$env:TEMP\sicacls-check` is gone; nothing outside it was touched.
