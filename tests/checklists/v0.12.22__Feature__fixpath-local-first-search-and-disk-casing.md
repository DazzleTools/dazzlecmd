# Human Test Checklist: fixpath local-first search and on-disk casing

**Target version:** 0.12.22
**Ships with commit:** v0.12.22 fix(fixpath): local matches win over same-named files elsewhere; paths print in on-disk casing
**Companion automated tests:** 20 tests in `src/dazzlecmd/projects/core/fixpath/tests/test_fixpath_search.py` (12 red-green anchors, 8 guards)

## What this is

A short hand-run check of `dz fixpath`'s search after two fixes: (1) on a drive indexed by Everything, a file under the current directory could lose to a same-named or substring-matching file elsewhere, because Everything's result cap was applied before filtering to the current directory; (2) an existing path typed in the wrong case printed as typed rather than as spelled on disk. The mocks cannot check the real Everything index, real fd, or how the stderr note reads in a terminal.

## Prerequisites

1. dazzlecmd 0.12.22 with `dz` on PATH; `fd` installed. Windows with Everything (es.exe) indexing the TEMP drive for HV.3; without Everything, HV.3 is skipped and everything else still applies (fd serves the local tiers).
2. **Always pass `-p`.** fixpath's default action is configurable, and a config of `default_action open` would launch your editor on every result. `-p` prints only.
3. Build the scratch tree. The target is 6 levels below the scratch root, so the 4-level walk-up cannot reach the decoys in `far\`.

   **cmd.exe**:
   ```cmd
   set FXP=%TEMP%\fxp-checklist
   mkdir "%FXP%\w1\w2\w3\w4\w5\here\notes" "%FXP%\far"
   echo x> "%FXP%\w1\w2\w3\w4\w5\here\notes\FXP-7731.md"
   echo x> "%FXP%\far\FXP-7731.md"
   echo x> "%FXP%\far\fxp-7731-far.md"
   cd /d "%FXP%\w1\w2\w3\w4\w5\here"
   ```

   **PowerShell**:
   ```powershell
   $FXP = "$env:TEMP\fxp-checklist"
   New-Item -ItemType Directory -Force "$FXP\w1\w2\w3\w4\w5\here\notes", "$FXP\far" | Out-Null
   "x" | Set-Content "$FXP\w1\w2\w3\w4\w5\here\notes\FXP-7731.md"
   "x" | Set-Content "$FXP\far\FXP-7731.md"
   "x" | Set-Content "$FXP\far\fxp-7731-far.md"
   Set-Location "$FXP\w1\w2\w3\w4\w5\here"
   ```

   **POSIX**:
   ```bash
   FXP="${TMPDIR:-/tmp}/fxp-checklist"
   mkdir -p "$FXP/w1/w2/w3/w4/w5/here/notes" "$FXP/far"
   echo x > "$FXP/w1/w2/w3/w4/w5/here/notes/FXP-7731.md"
   echo x > "$FXP/far/FXP-7731.md"
   echo x > "$FXP/far/fxp-7731-far.md"
   cd "$FXP/w1/w2/w3/w4/w5/here"
   ```

**Reset:** nothing is written by the checks; rerun any step in any order.

## High-Value Verification (~5 minutes)

All steps run from the `here` directory created above. Commands are `dz` only and identical across shells.

### HV.1 — A local file beats a same-named file elsewhere

Validates: search tiers run local-first; Everything is scoped to the current directory.

- [ ] **Steps:** `dz fixpath -p fxp-7731.md`
- [ ] **Expected:** prints `...\here\notes\FXP-7731.md` (not the one in `far\`), with no "elsewhere" note.
- [ ] **Why this matters:** this is the reported bug -- an unrelated file from another project was opened instead of the one next to you.

### HV.2 — An existing path prints in its on-disk casing

Validates: `fix_path` normalizes case for paths that already exist.

- [ ] **Steps:** `dz fixpath -p notes/fxp-7731.md`
- [ ] **Expected:** prints `...\here\notes\FXP-7731.md` -- capitals as on disk, not as typed.
- [ ] **Why this matters:** a path copied from fixpath output into a case-sensitive tool (git, a Linux share, a URL) must be the real name.

### HV.3 — Nothing nearby: drive-wide fallback is announced (needs Everything)

Validates: the last-resort tier runs only after local tiers fail, and says so.

- [ ] **Steps:** `dz fixpath -p fxp-7731-far.md`
- [ ] **Expected:** stderr line `(nothing under the current directory or 4 levels up; showing matches elsewhere on C:)` (your drive letter), then the path in `far\`.
- [ ] **Why this matters:** a far-away result is fine to offer, but must never pass as a local one.

### HV.4 — An explicit scope stays strict

Validates: `--search-on local` and `--dir` never fall back drive-wide.

- [ ] **Steps:** `dz fixpath -p --search-on local fxp-7731-far.md`, then `dz fixpath -p --dir . fxp-7731-far.md`
- [ ] **Expected:** both print `No matches for: fxp-7731-far.md` on stderr; stdout echoes the unresolved typed path (`...\here\fxp-7731-far.md`), and **neither prints the `far\` path**. Exit code is 0 under `-p` (print does not fail on a missing path; add `--verify` for a non-zero exit on not-found).
- [ ] **Why this matters:** tools that relink files (`md-rm-img` calls `dz fixpath --search-on local`) must not bind to a same-named file on the other side of the drive.

### HV.5 — `-q` silences the note but keeps the result

- [ ] **Steps:** `dz fixpath -p -q fxp-7731-far.md`
- [ ] **Expected:** the `far\` path on stdout, no stderr note. (Skip without Everything.)

## What the automated tests DO cover

| Area | Count |
|---|---|
| `-path` scoping; no global substitution; unscoped `--anywhere`; merged `--dir` roots | 5 |
| Tier order, walk-up via Everything on indexed drives (fd otherwise), announced last resort, `-q`, strict `local` / `--dir`, `--anywhere` | 11 |
| On-disk casing (`_true_case`, `fix_path`, `main -p`) | 4 |

All run against a fake es.exe and fake fd; none touch the real index or open a file.

## What the automated tests DON'T cover

- The real Everything index: its sort order, `-path` semantics, and how quickly new files appear.
- Real fd behavior on junctions, long paths, and permission-denied directories.
- How the stderr note reads in a real terminal next to the `(N matches, using best ...)` line.
- Casing on network shares (UNC paths are not case-normalized) and on case-sensitive filesystems.
- Performance feel of the extra `listdir` per path component on very large directories.
- Timing of a miss: on an indexed drive the walk-up uses Everything (a miss from a typical project directory measured ~4.6 s, dominated by fd's pass over the current tree); without Everything the walk-up is an fd crawl and can take tens of seconds from a high directory.

## Reporting issues found

Note the step (e.g. HV.3), the exact command, stdout and stderr, and whether Everything is installed; file an issue referencing this checklist and v0.12.22.

## Cleanup

**cmd.exe**: `cd /d %TEMP% && dz safedel -r --yes "%FXP%"`
**PowerShell**: `Set-Location $env:TEMP; dz safedel -r --yes "$FXP"`
**POSIX**: `cd "${TMPDIR:-/tmp}" && dz safedel -r --yes "$FXP"`
