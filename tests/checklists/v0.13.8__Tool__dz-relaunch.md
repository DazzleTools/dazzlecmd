# v0.13.8 -- Tool -- dz relaunch (human checklist)

What the automated suite (141+ tests, `src/dazzlecmd/projects/dazzletools/relaunch/tests`) cannot cover: real tabs, a real restart, real csb and claude sessions, keystrokes, and your eyes on the output.

## Prerequisites

- [ ] dazzlecmd 0.13.8 installed editable; dazzle-filekit 0.5.3 (editable checkout) importable: `python -c "import dazzle_filekit.locking"`.
- [ ] A practice store, so nothing touches your real one: `set DZ_RELAUNCH_HOME=%TEMP%\relaunch-practice` (unset it for the real drill).
- [ ] `dz relaunch shell-init cmd > <a local PATH folder>\dzr.cmd` (e.g. the folder holding `dz.exe`).

## 1. Build a set by hand

- [ ] `dz relaunch new practice` -> `relaunch: CREATED practice 0 members`.
- [ ] In three tabs, each in a different folder: `dzr practice add --here` -> each says `claimed practice:<n> for this tab`.
- [ ] `dz relaunch practice` shows three members, one `this tab`, two `claimed (pid N)`, and `next: nothing free`.
- [ ] `dz relaunch practice add --label codex -- codex resume --last` (or any harmless program) -> a command member.

## 2. Claim in fresh tabs

- [ ] Close the three tabs. Open a new tab: `dzr practice claim` -> it takes a member tagged `[open last session -- closed this boot]`, and **the tab ends up in that member's folder** (check the prompt).
- [ ] Same tab, again: `dzr practice claim` -> `(this tab already had it)`, same folder.
- [ ] Second new tab: the next member; `dz relaunch practice` shows both as claimed.
- [ ] A folder whose name has a space, `&` or `!` works the same (the wrapper was tested on these; confirm in your own shell, Dazzle setenv tab included).

## 3. `claim -o`

- [ ] `dzr practice claim codex -o` -> shows `will run: ...` and asks `[y/N]`; `n` -> nothing runs, `relaunch: REFUSED`.
- [ ] Again with `y` -> the program starts in this tab; quitting it leaves you in the member's folder; `echo %ERRORLEVEL%` is the program's exit code.
- [ ] Edit the command by hand in `%DZ_RELAUNCH_HOME%\sets\practice.json`, then `dzr practice claim codex -o -y` -> it still asks, saying the command is not the one relaunch recorded.

## 4. POC-3 -- csb and claude under relaunch (the maintainer's; gates Claude members' `-o`)

Follow the ten steps in `2026-11-19__15-25-32__DISCUSS_Rnd2_Brainstorm_relaunch-design.md`, section 5 (P3-1 .. P3-10), with `dz relaunch <set> claim <claude member> -o` in place of the stand-in script where it fits. Decision rule from that section: P3-1, P3-2, P3-3, P3-6 and P3-7 must pass.

- [ ] typing, arrows, Esc behave as with plain `csb resume`
- [ ] Ctrl-C during a turn stops the turn, not the session
- [ ] csb's "appears to be open already" prompt reads a keystroke
- [ ] `/exit` returns to cmd in the member's folder

## 5. The restart drill (AC-RESTART-DRILL)

- [ ] With your real store (unset `DZ_RELAUNCH_HOME`): build sets for the projects you have open (`new <set> --from-csb current` covers the Claude tabs; `add --here` the rest).
- [ ] Restart the machine. Open Terminal: `dz relaunch` shows each set with how many members were open last session.
- [ ] Open a window per set and run `dzr <set> claim` (or `-o`) in each new tab until each set says `nothing left to claim`.
- [ ] No `release --all` was needed. Time it against the old 10-20 minutes: ______

## 6. Early-adopter fiber probe (writes your real property store)

- [ ] `dz prop add relaunch:practice:1.notes "probe"`, then `dz prop get relaunch:practice:1.notes`, then `dz info relaunch:practice:1`. Record what each did in the relaunch vault's early-adopter log (expected today: prop stores it with no node check; `dz info` does not know the node).

## 7. Removal

- [ ] `dz relaunch practice drop rm 4` -> `dz relaunch list --removed` shows `practice:4`.
- [ ] `dz relaunch practice drop rm` -> asks; `y` -> `dz safedel recover <batch>` line printed; `dz relaunch list --removed` shows the set; recover it with that command.

## What mocks do not cover

Real Windows Terminal tab processes, `dzr` in your own (setenv) cmd, Ctrl-C delivery to a grandchild, csb's real JSON, a real reboot's boot time, Linux (not yet run there).

## Cleanup

- [ ] `dz safedel %TEMP%\relaunch-practice`; delete the practice `dzr` copy if you made one elsewhere.
