# Human Test Checklist: dz link-mirror -- NTFS link reconciliation after a file-level mirror

**Target version:** v0.12.4-alpha (dazzlecmd), with dazzle-preservelib 0.9.x (linkmirror engine) and dazzle-filekit 0.3.4 (link fidelity fixes)
**Ships with commit:** TBD (pre-commit checklist)
**Companion automated tests:** 58 new tests across three repos -- dazzle-filekit `tests/test_link_fidelity_v034.py` (6), dazzle-preservelib `tests/test_linkmirror_engine.py` (8) + `tests/test_linkmirror_mft.py` (36), dazzlecmd `src/dazzlecmd/projects/core/link-mirror/tests/test_link_mirror.py` (8). Full-suite counts at authoring time: filekit 440 passed / 11 skipped; preservelib 215 passed / 3 skipped.

## What this is

`dz link-mirror` recreates the NTFS links (symlinks, junctions, hardlink groups) that a file-level mirror (robocopy, Beyond Compare) silently drops. This checklist is the human pass over everything the mocks can't see: elevated MFT scans, real drive-to-drive migration behavior, disk-health monitoring during scans on failing hardware, UAC/Developer Mode variance, and terminal rendering. Run it before shipping the tool and before trusting it for a real migration.

## Prerequisites

1. Windows 10/11, NTFS volumes. Python 3.12+ (3.13 used at authoring). `dz` on PATH with dazzlecmd, dazzle-preservelib, and dazzle-filekit at the versions above.
2. A scratch directory on an NTFS drive (examples use `%TEMP%\lmtest`). No admin needed except Section 5 (MFT backend).
3. **State isolation**: everything here writes only inside the scratch directory (and, in Section 6 only, a designated real mirror pair you own). `dz link-mirror` itself never writes without `--apply`.
4. Reset between sections: delete the scratch directory.

   **cmd.exe**: `rmdir /s /q %TEMP%\lmtest`
   **PowerShell**: `Remove-Item -Recurse -Force $env:TEMP\lmtest`
   **POSIX**: n/a (Windows-only tool surface; engine walk/apply paths are cross-platform but junctions/MFT are not)

Fixture builder used throughout (cross-shell; save as `%TEMP%\make_fixture.py`):

```python
import os, sys
from dazzle_filekit.links import create_junction_raw
base = sys.argv[1]
src, dst = os.path.join(base, "src"), os.path.join(base, "dst")
for b in (src, dst):

os.symlink(r"..\data\file2.txt", os.path.join(L, "rel_file_link"))
os.symlink(r"..\data\real_dir", os.path.join(L, "rel_dir_link"), target_is_directory=True)
os.symlink(r"data\missing.txt", os.path.join(L, "broken_file_link"))
os.symlink(r"no\such\dir", os.path.join(L, "broken_dir_link"), target_is_directory=True)

create_junction_raw(os.path.join(src, "data", "real_dir"), os.path.join(src, "junc", "junc_ok"))
```

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these 6. Together they prove the tool ships: dry-run safety, faithful recreation (including the broken-link and timestamp guarantees), idempotency, and the opt-in hardlink path.

### HV.1 -- Dry-run by default changes nothing and exits 2

Validates: the safety contract every other behavior sits on.

- [ ] **Steps** (PowerShell):
  ```powershell
  python $env:TEMP\make_fixture.py $env:TEMP\lmtest
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst
  echo "exit=$LASTEXITCODE"
  Get-ChildItem -Force $env:TEMP\lmtest\dst\links
  ```
- [ ] **Expected:** plan reports `7 create, 1 hardlink_report`; `would create: 7 link(s)`; exit=2; `dst\links` is still EMPTY.
- [ ] **Why this matters:** if the default writes, the tool cannot be trusted near a 14TB migration.

### HV.2 -- Apply recreates every link kind with verbatim targets

Validates: symlinks (relative/absolute/broken, file+dir kind) and junctions (healthy+broken) are recreated byte-identically.

- [ ] **Steps** (PowerShell):
  ```powershell
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --apply --verify
  echo "exit=$LASTEXITCODE"
  ```
- [ ] **Expected:** `created: 7 link(s)`, `parent dir timestamps restored`, `verify: MISMATCH -- 7/8` with exactly ONE issue (the hardlink group, expected in report mode), exit=2.
- [ ] **Check** the broken link survived verbatim (PowerShell):
  ```powershell
  python -c "import os; print(os.readlink(os.environ['TEMP'] + r'\lmtest\dst\links\broken_file_link'))"
  ```
  prints `data\missing.txt` -- relative, unresolved, still broken.
- [ ] **Why this matters:** verbatim-and-broken preservation is the founding requirement; resolving or "fixing" targets corrupts the mirror.

### HV.3 -- Broken DIRECTORY symlink keeps directory kind

Validates: filekit fix -- kind comes from the source link node, not the (missing) target.

- [ ] **Steps** (PowerShell):
  ```powershell
  python -c "import os; a=os.lstat(os.environ['TEMP'] + r'\lmtest\dst\links\broken_dir_link').st_file_attributes; print('DIR bit:', bool(a & 0x10))"
  ```
- [ ] **Expected:** `DIR bit: True`.
- [ ] **Why this matters:** a dir symlink recreated as a file symlink dereferences wrongly forever after the target reappears.

### HV.4 -- Link timestamps match the source exactly

Validates: the 100ns-exact FILETIME path (filekit `_set_link_times_exact_windows`).

- [ ] **Steps** (PowerShell):
  ```powershell
  python -c "import os; e=os.environ['TEMP']; d=os.lstat(e + r'\lmtest\src\links\rel_file_link'); b=os.lstat(e + r'\lmtest\dst\links\rel_file_link'); print(d.st_mtime_ns == b.st_mtime_ns, d.st_birthtime_ns == b.st_birthtime_ns)"
  ```
- [ ] **Expected:** `True True` -- nanosecond-identical, not merely close.
- [ ] **Why this matters:** "mtimes/ctimes carefully transported" was an explicit migration requirement; anything lossy shows up in verify forever.

### HV.5 -- Idempotent re-run is a no-op

- [ ] **Steps:** re-run `dz link-mirror <src> <dst>` (dry-run).
- [ ] **Expected:** `plan: 7 satisfied, 1 hardlink_report`, `already satisfied: 7`, exit=0.
- [ ] **Why this matters:** a crashed or partial apply must be resumable by simply re-running.

### HV.6 -- Hardlink recreate is opt-in and completes verify

- [ ] **Steps:**
  ```powershell
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --apply --verify --hardlinks recreate
  echo "exit=$LASTEXITCODE"
  ```
- [ ] **Expected:** `hardlinked: 1 duplicate(s)`, `verify: OK -- 8/8 satisfied`, exit=0.
- [ ] **Why this matters:** this is the one destructive mode; it must never engage without the flag (HV.2 proved report mode left dupes alone).

## Section 1: Conflict safety (~5 min)

### 1.1 Wrong pre-existing link is reported, never overwritten

- [ ] **Steps** (PowerShell; fresh fixture):
  ```powershell
  Remove-Item -Recurse -Force $env:TEMP\lmtest; python $env:TEMP\make_fixture.py $env:TEMP\lmtest
  python -c "import os; os.symlink('wrong-target', os.environ['TEMP'] + r'\lmtest\dst\links\rel_file_link')"
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --apply
  echo "exit=$LASTEXITCODE"
  python -c "import os; print(os.readlink(os.environ['TEMP'] + r'\lmtest\dst\links\rel_file_link'))"
  ```
- [ ] **Expected:** CONFLICT line naming the path with `existing link target 'wrong-target' != expected ...`; exit=2; readlink still prints `wrong-target`. Other links created normally.

### 1.2 Plain file in a link's place is a conflict

- [ ] **Steps:** put a regular file at `dst\links\broken_file_link` before apply.
- [ ] **Expected:** `destination exists and is not a link` conflict; file content untouched.

### 1.3 Hardlink recreate refuses divergent content

- [ ] **Steps:** after a full apply, overwrite `dst\hl\b.txt` with different content; run `--apply --hardlinks recreate`.
- [ ] **Expected:** `ERROR: ... content differs from canonical ... refusing to replace`; exit=1; the divergent file is untouched.

## Section 2: Target rewrite policy (~3 min)

### 2.1 --rewrite-prefix rewrites absolute targets only

- [ ] **Steps** (fresh fixture; PowerShell):
  ```powershell
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --apply --rewrite-prefix $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --verify
  ```
- [ ] **Expected:** exit=2 with ONE remaining verify caveat class at most (hardlink report); `abs_file_link` on dst now points inside `dst` (check with `os.readlink`); ALL relative and broken targets unchanged. Junction `junc_ok` target rewritten too (both were absolute into src).
- [ ] **Note:** `--verify` uses the same policy, so rewritten targets verify as satisfied -- confirm no `target` issues appear.

## Section 3: Manifest save/load and JSON (~3 min)

### 3.1 Manifest round-trip

- [ ] **Steps:** `--save-manifest %TEMP%\lm.json` on a dry-run, inspect with `python -m json.tool`, then `--load-manifest %TEMP%\lm.json --apply`.
- [ ] **Expected:** JSON contains `records` with `kind/rel_path/target/is_dir/...`; the load-apply run creates the links WITHOUT re-scanning the source (fast even on a slow drive).

### 3.2 --json output shape

- [ ] **Steps:** `dz link-mirror <src> <dst> --json | python -m json.tool`
- [ ] **Expected:** valid JSON with `plan`, `dry_run: true`, `created`, `conflicts`, `errors`, `backend: "walk"`. No stray non-JSON lines on stdout.

## Section 4: Rendering and UX (mocks cannot see this) (~5 min)

### 4.1 Table output in cmd.exe (codepage 437)

- [ ] **Steps** (cmd.exe): run the HV.1 dry-run with `-v`.
- [ ] **Expected:** pure-ASCII output (`->` arrows, no Unicode); aligned columns; CONFLICT/CREATE labels scannable; no garbled characters.

### 4.2 Long paths do not wrap into unreadability

- [ ] **Steps:** run against a fixture nested several directories deep (or the real Section 6 pair) in a default-width terminal.
- [ ] **Expected:** one line per item; your judgment call -- is the output usable at 120 cols? Note anything painful.

### 4.3 Error message quality

- [ ] **Steps:** `dz link-mirror C:\nonexistent %TEMP%` and `dz link-mirror --backend mft <src> <dst>` from a NON-elevated console.
- [ ] **Expected:** clear one-line errors: source-not-a-directory; MFT requires elevation with the hint to elevate. Exit=1 for both. No tracebacks.

## Section 5: MFT backend (requires an ELEVATED console) (~10 min)

Skip this section if you cannot elevate. The `auto` backend silently falls back to walk when not elevated -- Sections 1-4 all exercise the walk backend.

### 5.1 is_mft_available and explicit backend selection

- [ ] **Steps** (elevated PowerShell):
  ```powershell
  dz link-mirror $env:TEMP\lmtest\src $env:TEMP\lmtest\dst --backend mft --save-manifest $env:TEMP\lm-mft.json
  ```
- [ ] **Expected:** scan completes without elevation errors; manifest saved with `"backend": "mft"`.

### 5.2 Walk/MFT parity (acceptance check 10)

- [ ] **Steps** (elevated; after 5.1 and a walk `--save-manifest %TEMP%\lm-walk.json` over the same fixture):
  ```powershell
  python -c "import json,os; e=os.environ['TEMP']; a=json.load(open(e+r'\lm-walk.json')); b=json.load(open(e+r'\lm-mft.json')); ka={(r['kind'],r['rel_path'],r['target']) for r in a['records']}; kb={(r['kind'],r['rel_path'],r['target']) for r in b['records']}; print('walk-only:', ka-kb); print('mft-only:', kb-ka)"
  ```
- [ ] **Expected:** both sets empty (identical kind/rel_path/target inventory). Hardlink group ids may differ in representation but group MEMBERSHIP must match.
- [ ] **Why this matters:** the MFT parser's hardlink-representation assumption (one USN record per name, shared FRN) was documented but could not be live-verified unelevated during development. THIS is the step that verifies it.

### 5.3 MFT scan of a large real volume (timing + memory)

- [ ] **Steps** (elevated): `dz link-mirror D:\ B:\ --backend mft --hardlinks skip --save-manifest %TEMP%\d-links.json` (dry-run -- no --apply).
- [ ] **Expected:** completes in minutes (not hours); watch Task Manager -- the FRN map costs memory at scale (estimated ~13-15 GB at ~50M records; acceptable on a 32GB box, abort if the machine starts paging hard).
- [ ] **Check:** record counts in the saved manifest look plausible; `errors` list reviewed.

## Section 6: Real migration pass (the reason this tool exists) (~15 min + review)

Only run against a mirror pair you own, with the source drive's health monitored. These steps mirror the D:->B: retirement flow.

### 6.1 Disk-retry monitoring during the scan (failing source drives)

- [ ] **Steps:** if the source drive has known link-layer errors, snapshot before/after the scan (project-specific tooling, e.g. `Get-DiskRetrySnapshot.ps1 -Csv`); run the scoped scan (`dz link-mirror D:\M B:\M --save-manifest ...`).
- [ ] **Expected:** SMART 199 CRC **delta** of zero (raw value never resets -- judge by delta) and no burst of Event-153 retries attributable to the scan.

### 6.2 Scoped dry-run -> review -> apply -> verify

- [ ] **Steps:** dry-run first; READ the report (creates, conflicts, excluded reparse tags, scan errors); only then `--apply`; then `--verify`.
- [ ] **Expected:** verify `OK` for the scoped tree, or every issue individually explainable. Review the excluded `other_reparse` list (OneDrive/WOF/appexec tags are inventory-only by design).

### 6.3 D:-absolute targets decision

- [ ] **Steps:** from the saved manifest, list absolute targets pointing at the retiring drive:
  ```powershell
  python -c "import json,os; m=json.load(open(os.environ['TEMP']+r'\d-links.json')); [print(r['rel_path'],'->',r['target']) for r in m['records'] if r['target'].replace('\\\\?\\','').lower().startswith('d:')]"
  ```
- [ ] **Expected:** a reviewed list; consciously choose verbatim (default) or `--rewrite-prefix D:\ B:\` BEFORE the drive is pulled. This is a decision gate, not an automatic step.

## What the automated tests DON'T cover

- **Elevated MFT enumeration against a live volume** -- the parser is tested on synthetic buffers only; Section 5 is the real verification (including the hardlink-FRN representation assumption).
- **Failing-hardware behavior** -- scan I/O on a drive with SATA-link CRC errors (Section 6.1).
- **Memory at 50M-record scale** (Section 5.3).
- **Terminal rendering** -- codepage 437/1252, column alignment, long-path wrapping (Section 4).
- **Error message clarity and elevation hints** (Section 4.3).
- **Cross-drive semantics of the real migration** -- ACL-denied subtrees, exotic reparse tags in the wild, robocopy artifacts (Section 6.2).
- **Performance feel** of walk vs MFT on real volumes.
