## What this is

The visibility verbs now resolve a user-typed name to its canonical FQCN before writing (fixing inert short-name writes + a C3 bypass), and the per-verb binding moved into a typed `VisibilityRung` payload on `KIT_PRESENCE_SPACE` (the CLI no longer carries verb/config tables). This checks the real-resolution gap the mocks don't cover.

## Prerequisites

Isolated config (cmd: `set DAZZLECMD_CONFIG=%TEMP%\dz37.json` / PowerShell: `$env:DAZZLECMD_CONFIG="$env:TEMP\dz37.json"` / POSIX: `export DAZZLECMD_CONFIG=/tmp/dz37.json`). Reset by deleting that file.

## High-Value Verification (~3 min)

### HV.1 -- Short name resolves to canonical (effective, not inert)
- [ ] `dz kit visibility silence safedel`
- [ ] **Expected:** prints `Silenced: core:safedel` (the CANONICAL, not `safedel`); the config's `silenced_hints.tools` contains `core:safedel`.
- [ ] **Why:** a short name written verbatim never matched the FQCN filters -- a silent no-op. This is the fix.

### HV.2 -- C3 cannot be dodged by short name
- [ ] `dz kit visibility shadow safedel`
- [ ] **Expected:** `Refused: core:safedel is constitutional ...`, exit 1; `core:safedel`/`safedel` NOT in `shadowed_tools`.
- [ ] **Why:** before, the short name bypassed the constitutional guard (wrote an inert `safedel`).

### HV.3 -- Unknown name warns, doesn't silently write inert
- [ ] `dz kit visibility hide totally-bogus-xyz`
- [ ] **Expected:** a `Note: '...' didn't resolve ... recording as-is` warning on stderr (not a silent success).
- [ ] **Why:** typos/forward-refs are surfaced, not buried.

### HV.4 -- status reads the typed rungs + resolves (normal tool)
- [ ] `dz kit visibility hide find` then `dz kit visibility status find`
- [ ] **Expected:** `core:find` / `presence: hidden`; `less visible -> dz kit visibility shadow core:find`; `more visible -> dz kit visibility unhide core:find`.
- [ ] **Why:** the navigator's verbs + the current level both come from the `VisibilityRung` payloads (no in-CLI tables).

### HV.5 -- the navigator is C3-aware (no dead-end suggestions)
- [ ] `dz kit visibility hide safedel` then `dz kit visibility status safedel`
- [ ] **Expected:** `presence: hidden`; `less visible -> (none: core:safedel is constitutional -- 'shadow' refused by C3; hidden is the max veil)`. It does NOT print `dz kit visibility shadow ...`.
- [ ] **Why:** `shadow` on a constitutional tool is C3-refused; the navigator must not recommend a move the surface will reject (the gap this closes).
