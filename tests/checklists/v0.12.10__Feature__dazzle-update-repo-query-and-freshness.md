# Human Test Checklist: dz dazzle-update Repo Query + Freshness Architecture

**Target version:** 0.12.10-alpha
**Ships with commit:** TBD (feature: single-repo detail card, cache-index freshness model, three identity/scope bug fixes)
**Companion automated tests:** 23 in `dazzle-update/tests/test_query.py`, 2 in `test_ecosystem.py::TestRedirectFromLiveCheckoutsOnly`, 1 in `test_config.py`; tool suite 219, full repo suite 2288.

## What this is

`dz dazzle-update <name>` now answers "everything about one repo" as a detail card -- identity, every checkout, install, PyPI, set membership, findings -- matched by owner/repo name, dist name, or checkout folder name, plain or globbed. It returns in under a second because the population comes from the scan cache (an index) while the *matched* repos are verified live. This checklist covers what mocks cannot: real timing feel, real remote behavior, and the honesty of the provenance disclosures under conditions that are hard to fake.

## High-Value Verification (~5 minutes)

### HV.1 -- The bare query is fast and complete

- [ ] **Steps:** `dz dazzle-update dazzlesum` (substitute any repo you have)
- [ ] **Expected:** a card in roughly a second showing identity, checkouts (primary marked `*`, excluded tagged), install, sets, findings; a two-line provenance header; a bottom stats line ending in elapsed seconds.
- [ ] **Why this matters:** the entire feature -- if this is slow or thin, nothing else matters.

### HV.2 -- Matched repos are verified LIVE, not replayed

- [ ] **Steps:** touch a file in a repo (`echo x >> README.md`), then query that repo.
- [ ] **Expected:** the card shows the new dirty count immediately, even though the population cache predates the edit. Stats line says `verified live just now`.
- [ ] **Why this matters:** the whole justification for not using pure cache. Undo the edit afterward.

### HV.3 -- Fixing a remote clears its finding immediately

- [ ] **Steps:** on a repo showing `stale-remote-url`, run `git remote set-url origin <canonical URL>`, then query it.
- [ ] **Expected:** the finding is gone on the very next query -- no full rescan needed.
- [ ] **Why this matters:** the card contradicting a fix you just made is the worst moment to be wrong (this was a real bug, found live).

### HV.4 -- Archived copies do not flag the live repo

- [ ] **Steps:** query a repo that has excluded `baks/` copies with older remote URLs (e.g. dazzlesum).
- [ ] **Expected:** excluded checkouts are listed and tagged `[excluded]`, but their stale URLs do NOT produce a `stale-remote-url` finding for the repo.
- [ ] **Why this matters:** a frozen snapshot is not an actionable problem; reporting it made a correct repo look broken.

### HV.5 -- A narrowed scan cannot corrupt the index

- [ ] **Steps:** `dz dazzle-update --root C:\code\<one-project>` then immediately `dz dazzle-update <some repo outside that root>`.
- [ ] **Expected:** the second command still answers against the FULL population (check the `N repos` count in the stats line matches your usual total), because the narrowed scan did not overwrite the shared cache.
- [ ] **Why this matters:** a scoped run silently shrinking the index is invisible until a count moves.

## Section 1: Matching (~3 min)

### 1.1 The three match surfaces
- [ ] By bare repo name (`dazzlesum`), by full name (`DazzleTools/dazzlesum`), by dist name, and by checkout folder name -- all find the same record.
- [ ] Case-insensitive both directions.

### 1.2 Globs and misses
- [ ] `dz dazzle-update "wtf-*"` returns the whole family (quote it -- your shell may expand it).
- [ ] A wide glob (`"dazzle*"`) live-refreshes at most 8 and says how many came from cache.
- [ ] A nonsense name exits 2 with guidance, printing nothing that looks like a result.

## Section 2: Freshness and provenance (~5 min)

### 2.1 Flag semantics
- [ ] `--cached <name>` -- replays, never fetches (fast, works offline).
- [ ] `--no-fetch <name>` -- re-reads locally; stats line says behind-counts came from the last fetch.
- [ ] `--no-cache <name>` -- full fresh scan (slow; the pre-0.12.10 behavior).

### 2.2 Provenance honesty
- [ ] Header states population age, namespaces/repos covered, and the governing config.
- [ ] Query with a different `--config` than the one that wrote the cache: a warning names BOTH config paths.
- [ ] Delete the scan cache, then query: a first-run notice explains the one-time full scan.

### 2.3 Offline behavior
- [ ] Disconnect the network, query a repo: fetch failures are counted in the stats line; behind-counts are not presented as live; the command still completes.

## Section 3: Verbosity and output (~3 min)

- [ ] `-v` prints `[timing] total N.NNs` to stderr; `-vv` adds the per-phase breakdown.
- [ ] Timing goes to **stderr**: `dz dazzle-update <name> --json > out.json` leaves `out.json` valid JSON.
- [ ] `--json <name>` emits `{schema, query, matches}`.
- [ ] `<name> --fix` refuses with a read-only message, exit 2.

## What the automated tests DO cover

Matching semantics (all surfaces, globs, one-directional substring), card rendering per axis, no-match exit, JSON shape, `--fix` guard, live refresh visibility (real git repos), excluded-checkout skipping, the refresh cap, `--cached` purity, scope-mismatch and narrowed-cache warnings, identity re-resolution, and the join-level redirect/exclusion rule.

## What the automated tests DON'T cover

- Real wall-clock feel (tests assert by construction, never by timing)
- Real network: fetch through an actual redirect, real offline behavior, slow remotes
- Terminal rendering of the card and stats line (colour, alignment, width, `NO_COLOR`)
- Whether the card shows the axes YOU actually want at a glance
- Shell glob expansion differences (cmd.exe vs PowerShell vs bash)
- Cache interactions across concurrent invocations

## Reporting issues found

Include the exact command, the full card, the provenance header, and `git status --porcelain` for the repo in question. For matching disputes, add `--json`.

## Cleanup

Undo any file touched in HV.2. If you deleted the scan cache for 2.2, run `dz dazzle-update` once to rebuild it.
