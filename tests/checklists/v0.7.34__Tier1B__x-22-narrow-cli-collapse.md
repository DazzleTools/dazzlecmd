# Human Test Checklist: v0.7.34 — Tier 1B — X-22-narrow CLI collapse

**Target version:** v0.7.34 **Ships with commit:** TBD (Tier 1 commit 6, the X-22-narrow CLI collapse) **Companion automated tests:** 959 passed, 13 skipped (down from 984 — `tests/test_cli_info.py` deleted; library has equivalent integration coverage)

## What this is

v0.7.34 collapses dazzlecmd's `_cmd_list`, `_cmd_info`, and `_cmd_tree` from full implementations (~580 combined LOC of body) to thin wrappers over the library equivalents. The library was extended in this same commit to reach byte-equivalence parity for `render_tree` (`--show-disabled`, canonical-kit `[always_active]` / `[aggregator]` / `[disabled]` markers, kit-state computation from user config, JSON output extensions). One small library behavior change: `render_info` "tool not found" message now uses `engine.command` and prints to stdout (was bare `'list'` hint to stderr).

Cumulative net delete from `cli.py` across v0.7.30 → v0.7.34: about 950 lines (2521 → 1571). dazzlecmd is now a "thin instance" of dazzlecmd-lib for the list/info/tree surface, the same shape as amdead and wtf-windows.

2. dazzlecmd-lib editable install (auto via dazzlecmd)

4. wtf-windows installed in editable mode for live consumer verification (note: `wtf info` has a pre-existing bug -- skip that step)

## High-Value Verification (~5 minutes)

### HV.1 — `dz list` byte-equivalent to v0.7.33

- [ ] **Steps:** `dz list`
- [ ] **Expected:** Output identical to v0.7.33. Sectioned layout for multi-kit configs (Phase 4e v0.7.28); tools grouped under kit headers; footer count.
- [ ] **Why this matters:** If this differs, the collapse silently dropped behavior. The whole pre-implementation discipline is about preventing this.

### HV.2 — `dz info <tool>` byte-equivalent to v0.7.33

- [ ] **Steps:** `dz info safedel`
- [ ] **Expected:** Standard info banner -- Name / FQCN / Kit / Namespace / Version / Description / Platform / Language / Runtime / Script / Category / Tags. No regression vs v0.7.33.
- [ ] **Why this matters:** Validates `_cmd_info` -> library `render_info` collapse.

### HV.3 — `dz info <missing>` not-found path uses `dz`

- [ ] **Steps:** `dz info this-tool-does-not-exist`
- [ ] **Expected:** `Tool 'this-tool-does-not-exist' not found. Use 'dz list' to see available tools.` to stdout. Exit code 1.
- [ ] **Why this matters:** The library not-found message now uses `engine.command` (was a bare `'list'` hint). For dazzlecmd this MUST say "Use 'dz list'" (not "Use 'list'").

### HV.4 — `dz tree` byte-equivalent to v0.7.33

- [ ] **Steps:** `dz tree`
- [ ] **Expected:** ASCII tree with kit headers, `[always_active]` / `[aggregator]` markers preserved, virtual-kit branches rendered with `[virtual]`, footer summary line. Identical to v0.7.33.
- [ ] **Why this matters:** Validates the tree-parity port + collapse.

### HV.5 — `dz tree --show-disabled` works

- [ ] **Steps:** `dz tree --show-disabled`
- [ ] **Expected:** Includes disabled kits with `[disabled]` marker. Tools from disabled kits visible.
- [ ] **Why this matters:** Validates that the dazzlecmd-only `--show-disabled` flag was successfully ported into the library.

### HV.6 — pytest baseline green

- [ ] **Steps:** `python -m pytest tests/ --ignore=projects/wtf -q`
- [ ] **Expected:** `959 passed, 13 skipped`. Note: down from 984 in v0.7.33 because `tests/test_cli_info.py` (23 tests) was deleted -- library has equivalent integration coverage.

## Section 1: `dz list` collapse

### 1.1 Default mode (alias-preferred)

- [ ] **Steps:** `dz list`
- [ ] **Expected:** Sectioned layout (multi-kit configs); virtual-kit aliases REPLACE their canonical targets; tools without aliases still shown.

### 1.2 `--show all` mode

- [ ] **Steps:** `dz list --show all`
- [ ] **Expected:** Both canonicals AND aliases shown; canonicals with aliases are marked `[+]`. Footer note explains the marker if any are present.

### 1.3 `--show canonical` mode

- [ ] **Steps:** `dz list --show canonical`
- [ ] **Expected:** Canonicals only. Script-stable legacy view -- safe for parsing.

### 1.4 `--show alias` mode

- [ ] **Steps:** `dz list --show alias`
- [ ] **Expected:** Virtual-kit aliases only.

### 1.5 Filter combinations

- [ ] **Steps:** `dz list --kit core` then `dz list --tag windows` then `dz list --platform cross-platform`
- [ ] **Expected:** Filters work as before. Empty output if no matches.

### 1.6 Single-section flat fallback

- [ ] **Steps:** Find a kit with only one section. Run `dz list --kit <that-kit>`.
- [ ] **Expected:** Flat table layout (Name / Kit / Description columns), not sectioned layout.

## Section 2: `dz info` collapse

### 2.1 Standard tool

- [ ] **Steps:** `dz info safedel`
- [ ] **Expected:** Full banner unchanged from v0.7.33.

### 2.2 `--raw` flag

- [ ] **Steps:** Find a tool with conditional dispatch. `dz info <tool> --raw`
- [ ] **Expected:** Runtime line shows `(raw, unresolved)` marker; `_vars` (manifest-top + runtime block) shown if present; `Platforms:` and `Prefer:` listed.

### 2.3 `--platform SPEC` flag

- [ ] **Steps:** `dz info <tool> --platform linux`
- [ ] **Expected:** Runtime line shows `(preview for linux)`; per-platform overrides visible.

### 2.4 Qualified-alias provenance

- [ ] **Steps:** Find a virtual-kit alias (e.g., `dazzletools:claude:cleanup`). `dz info dazzletools:claude:cleanup`
- [ ] **Expected:** First line: `(qualified alias 'dazzletools:claude:cleanup' = 'dazzletools:claude:cleanup' -> canonical 'X')`.

### 2.5 Shadow status

- [ ] **Steps:** Find a tool whose short name shadows a meta-command. `dz info <that-tool>`
- [ ] **Expected:** "Shadow status:" block surfaces the dispatch state.

### 2.6 Linked-project line

- [ ] **Steps:** Find a tool whose `_dir` is a symlink/junction. `dz info <that-tool>`
- [ ] **Expected:** "Linked to: <target>" line at the bottom of the info banner.

### 2.7 Not-found path

- [ ] **Steps:** `dz info nonexistent-tool-name`
- [ ] **Expected:** `Tool 'nonexistent-tool-name' not found. Use 'dz list' to see available tools.` Exit code 1. Output goes to stdout (not stderr).

## Section 3: `dz tree` collapse + parity port

- [ ] **Steps:** `dz tree --depth 1`
- [ ] **Expected:** Only kits, no tools.

### 3.5 `--kit <name>` filter

- [ ] **Steps:** `dz tree --kit core`
- [ ] **Expected:** Only the core branch rendered.

### 3.6 Aggregator marker

- [ ] **Steps:** Find a kit with its own `kits/` subdir (e.g., `wtf` if imported as a kit). `dz tree`
- [ ] **Expected:** That kit's header shows `[aggregator]` marker.

### 3.7 Always-active marker

- [ ] **Steps:** Find a kit with `always_active: true` in its manifest. `dz tree`
- [ ] **Expected:** That kit's header shows `[always_active]` marker.
