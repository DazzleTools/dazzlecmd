# Human Test Checklist: DazzleEntity dict-shim deletion (lib 0.8.0, breaking)

**Target version:** dazzlecmd v0.8.30 / dazzlecmd-lib **0.8.0** (breaking)
**Ships with commit:** state-system Step 6 — shim deletion / migration close
**Companion automated tests:** full suite **1356 passed / 14 skipped**; byte-gate **10 OK / 0 FAIL**; `tests/test_ratchet_enforcement.py` (post-shim regression: key ops run + shim gone + extra_get/set)

## What this is

The breaking close of the DazzleEntity migration. The dict shim — which let every call site treat an entity like a dict (`project["_fqcn"]`, `kit.get("manifest")`) — is **deleted**. Entities now expose typed attributes (`entity.runtime`, `entity.fqcn`) plus `extra_get`/`extra_set`/`has_extra` for the untyped remainder (`source`, `_vars`, `manifest`). ~293 call sites across prod + tests were migrated. This checklist verifies the human-facing surface: that real `dz` invocations still work end-to-end with the shim removed, that dispatch is unchanged, and that the consumer (wtf) is unaffected. The byte-gate proves prod output is byte-identical; this confirms it at the terminal.

## High-Value Verification (~5 minutes)

### HV.1 — The read surfaces run post-shim
- [ ] **Steps:** `dz list` · `dz list --show all` · `dz tree` · `dz info core:find` · `dz mode status` · `dz kit list` · `dz kit status`
- [ ] **Expected:** every command runs and prints normally (no `AttributeError: object has no attribute 'get'`, no traceback).
- [ ] **Why this matters:** these are the paths the shim used to back; if any prints a traceback, the migration missed a prod site.

### HV.2 — Dispatch still works (by short name AND FQCN)
- [ ] **Steps:** `dz find --help` (short name) · `dz core:safedel --help` (FQCN)
- [ ] **Expected:** both reach the tool and print its help.
- [ ] **Why this matters:** dispatch resolution walks entity fields; a missed migration there breaks running tools.

### HV.3 — `dz mode switch` on a sandboxed tool (no real submodules)
- [ ] **Steps:** in a throwaway dir, exercise `dz mode status` / a dry-run switch on a scratch tool (never against a real submodule).
- [ ] **Expected:** mode resolution reads `source`/`lifecycle` via the new `extra_get` path without error.

### HV.4 — The consumer (wtf) is unaffected
- [ ] **Steps:** with the `wtf` kit active, `dz wtf` / `dz list` showing wtf tools; resolve a `wtf:core:*` tool.
- [ ] **Expected:** the nested aggregator (wtf) discovers + dispatches normally — wtf was already shim-clean, so deleting the shim must not change it.

### HV.5 — The breaking change is real
- [ ] **Steps (Python):** `python -c "from dazzlecmd_lib.testing import make_tool; t=make_tool(name='x',_fqcn='core:x'); print(t.fqcn, t.runtime); t.extra_set('source',{'url':'u'}); print(t.extra_get('source'));
  try:\n    t['name']\nexcept TypeError:\n    print('dict access correctly gone')"`
- [ ] **Expected:** prints the fqcn + `{}` runtime, the extra round-trip, and `dict access correctly gone`.
