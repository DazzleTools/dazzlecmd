## Prerequisites

- `dz` on PATH (any install mode). A populated aggregator (the stock dazzlecmd tree suffices).
- No config changes are made by this checklist except one reversible note write (cleaned in the last step).

## Section 1 — the entity plane (`:`)

- [ ] `dz info safedel` (BARE name) → the full identity card: Name/Short FQCN/Level rows, a `Fibers:` section, `Current state:` with no blank line after the header.
- [ ] `dz info :core:safedel` (PATH spelling) → the compact TREE card (kind/level/alias/contains) — a different rendering of the same node (the two-cards seam, open-looped for unification).
- [ ] `dz info dz:core:safedel` (ROOT-PREFIXED) → the same tree card — the tutorial's equivalence claim (blind-run finding #2, fixed by widening the tree-card gate).
- [ ] `dz info :dazzletools:claude` → a card with `kind: Unified (projection)`, a `source: dz:claude` line WITH a followable `(dz info :claude)` hint, and `contains:` listing short-named members (cleanup, view, …).
- [ ] Follow the hint: `dz info :claude` → the virtual kit's card.

## Section 2 — the property plane (`.`)

- [ ] `dz :core:safedel.version` → `0.1.1 (derived)` (value + the derived marker).
- [ ] `dz ":core:safedel.version=9"` → REJECTED (read-only; the message names the item's own data as the source). Exit code 2.
- [ ] `dz :.meta:config.list_view` → the live config value + `(derived)`.
- [ ] `dz ":.meta:config.anything=x"` → REJECTED with the file-truth message (works for ABSENT keys too — the phantom-write guard).

## Section 3 — the ring (`:.`)

- [ ] `dz info safedel:.` → `(the ring)` listing: `instance of` with followable handle; `alias f:rm` with `(dz info :core:safedel:.alias:f-rm)`.
- [ ] `dz info :core:safedel:.alias:f-rm` → the RELATION OBJECT's card (kind `alias-relation`).
- [ ] Write a note ON the relation: `dz ":core:safedel:.alias:f-rm.note=checklist probe"` → added. Read back via the COUNTERPART address: `dz :core:f:rm.note` → the value with `(from dz:core:safedel:.alias:f-rm.note)` echoed.
- [ ] The confusion case from the tutorial: `dz :.dazzletools:claude` → forgiveness echo (`-> dz.dazzletools:claude (canonical)`), then "has no value set" PLUS the note naming `dz:dazzletools exists (a kit)`, the operator rule, AND `IN FACT dz:dazzletools:claude exists (a projection)` with the exact info command.
- [ ] `dz :..meta` (dot-run) → parse error, not a silent anything.
- [ ] The two-dots test holds in both directions: `dz info :core:safedel:.alias:f-rm` renders a CARD (a ring entry is a node), while `dz info :core:safedel.version` does NOT render a version-card (a property is a value, not a place) — the tutorial's "if you can info it" rule is truthful.

## Section 4 — up and composition (`:+`)

- [ ] `dz info :.meta:level:.0:+` → the LEVEL AXIS card (deref to the seat, then up).
- [ ] `dz info :.meta:level:-2` → the tool rung (rank −2).
- [ ] `dz info :.meta:level:0` → the axis itself (zero = self), NOT the aggregator rung.
- [ ] `dz info :.meta:level:.0` → the aggregator rung (the ring's seat).
