# Human Test Checklist: Recoverable mode swaps (safedel) + embedded-tool enablement

**Target version:** dazzlecmd v0.9.2 (safedel adoption) + v0.9.3 (embedded enablement)
**Ships with commits:** `dbb2a37` (v0.9.2), `cb2f3c0` (v0.9.3)
**Companion automated tests:** `tests/test_mode_safedel.py` (7), `tests/test_mode_embedded.py` (5), `tests/one-offs/test_safedel_api_load.py` (load proof); existing mode suite (59); safedel's own suite (121).

## What this is

`dz mode switch` is now a **destructive-but-recoverable** operation: before it removes a tool directory (a submodule checkout or an embedded checkout), it stages that directory to safedel's trash store, so a mistaken or unwanted switch is recoverable via `dz safedel recover last`. v0.9.3 additionally enables mode-switching for **embedded** tools (checked out directly into the aggregator tree, no submodule), which previously refused with "no mode toggle available". Because this path **deletes directories**, the automated tests mock the trash call and use temp fixtures; this checklist exercises the **real** trash + recover round-trip and the real subprocess/filesystem behavior the mocks can't cover.

## Prerequisites

1. A dazzlecmd dev checkout (so `projects/core/safedel/` is present — dazzlecmd ships safedel).
2. A throwaway sandbox aggregator or tool dir — **NEVER run mode switch against a real submodule you care about.** Use `test_runs/` for scratch.
3. Know your trash store location: `dz safedel status` prints it (default `~/.safedel-trash`).
4. Reset between sections: `dz safedel list` to see entries; do NOT run `dz safedel clean` (humans only, and not needed here).

## High-Value Verification (~5 minutes)

### HV.1 — Embedded tool is now switchable (was refused)

Validates: item 3.5-1 — `_determine_target` returns "dev" for STATE_EMBEDDED.

- [ ] **Steps:** In a sandbox aggregator, create an embedded tool dir (a plain directory under `projects/<ns>/<tool>/` with a `.dazzlecmd.json`, NOT a submodule). Run `dz mode switch <tool> --path <some-local-repo> --dry-run`.
- [ ] **Expected:** Shows `Target: DEV (symlink)` and `Would remove: ...` / `Would create symlink: ...` — NOT "no mode toggle available".
- [ ] **Why this matters:** If this still refuses, 3.5-1 didn't ship and embedded tools remain unswitchable.

### HV.2 — Real swap stages to trash (recoverable), not rmtree

Validates: item 3.5-10/3.5-14 — the destructive site uses safedel.

- [ ] **Steps:** With the same embedded tool, run for real (no `--dry-run`): `dz mode switch <tool> --path <local-repo>`. Then `dz safedel list`.
- [ ] **Expected:** Output includes `Backed up to trash (recover with: dz safedel recover last)`; the embedded dir is now a symlink to `<local-repo>`; `dz safedel list` shows a fresh entry containing the old embedded content.
- [ ] **Why this matters:** This is the whole point — a wrong switch must be recoverable, not gone.

### HV.3 — Recover restores the original content

Validates: the round-trip — the backup is real, not cosmetic.

- [ ] **Steps:** `dz safedel recover last`.
- [ ] **Expected:** The original embedded directory content is restored from the trash store (verify a known file from the embedded dir is back). (Note: recovery restores the trashed dir to its original path; you may need to remove the symlink first depending on collision handling — observe and record the actual behavior.)
- [ ] **Why this matters:** Confirms recoverability end-to-end, the safety guarantee.

### HV.4 — `_schema_version` stamped in mode_local.json

Validates: item 3.5-12.

- [ ] **Steps:** After any switch that wrote a dev path, view `mode_local.json` in the aggregator root.
- [ ] **Expected (cross-shell):**
  - **cmd.exe:** `type mode_local.json | findstr _schema_version`
  - **PowerShell:** `Get-Content mode_local.json | Select-String _schema_version`
  - **POSIX:** `grep _schema_version mode_local.json`
  Shows `"_schema_version": 1`.
- [ ] **Why this matters:** Future config-format migrations rely on this stamp.

### HV.5 — Dirty-tree gate still fires (safety boundary intact)

Validates: the T1-E gate is still the hard boundary; safedel is additive.

- [ ] **Steps:** Make an uncommitted change in a submodule-mode tool's checkout, then `dz mode switch <tool>` (no `--force`).
- [ ] **Expected:** Refuses with "has uncommitted changes; refusing to switch"; nothing is deleted or trashed. With `--force`, it proceeds (and still trashes recoverably where safedel is present).
- [ ] **Why this matters:** The dirty-tree gate must not have regressed — it protects the dangerous case.

## Section 1: Fallback policy (the empirically-revised behavior)

### 1.1 safedel-present backup-failure aborts without --force

- [ ] **Steps:** Hard to trigger naturally; covered by `tests/test_mode_safedel.py::test_remove_backup_failure_aborts_without_force`. Manually: simulate by making the trash store unwritable (e.g., point `~/.safedel-trash` at a read-only path) and switch a clean tool.
- [ ] **Expected:** `safedel backup ... failed`; `Swap aborted (nothing deleted)`; the tool dir is intact; rc 1.
- [ ] **Why:** A failed backup must NOT proceed to deletion.

### 1.2 safedel-absent aggregator falls back to rmtree (backward-compat)

- [ ] **Steps:** On an aggregator WITHOUT safedel (e.g. a minimal aggregator, or wtf-windows/amdead which don't ship safedel), switch a clean tool.
- [ ] **Expected:** `Note: safedel not available here; removing <dir> without a recovery backup.` then the swap proceeds — NO hard refusal. (Policy note: this is the backward-compatible default; it is flippable to strict-refuse — see the import-mechanism DWP.)
- [ ] **Why:** The "clean tree switches freely" contract for non-safedel aggregators is preserved.

## Section 2: Cross-aggregator (tools_dir parameterization)

### 2.1 The safedel path resolves under the aggregator's tools_dir

- [ ] **Steps:** Confirm `_load_safedel_api` anchors on `<project_root>/<tools_dir>/core/safedel`. For dazzlecmd `tools_dir="projects"`; for wtf/amdead `tools_dir="tools"` (which have no safedel -> absent fallback).
- [ ] **Expected:** dazzlecmd finds safedel and trashes; wtf/amdead don't find it and fall back.

## What the automated tests DON'T cover (this checklist's job)

- The **real** safedel trash + recover round-trip via `dz mode switch` (mocks stub the trash call; fixtures lack safedel).
- Real symlink/junction creation on Windows after the trashed-removal (PowerShell `New-Item`).
- Trash-store collision behavior when recovering over an existing symlink.
- The note/warning wording readability on real terminals (cmd codepage).
- Behavior when the trash store is on a different volume than the tool dir.

## Reporting issues found

1. Note the section/step. 2. Capture the exact command + output. 3. Save `mode_local.json` + `dz safedel list` output. 4. File against #37 (mode) or #38 (safedel), referencing this checklist + commit.

## Cleanup

- `dz safedel list` to see what this checklist staged; recover anything you want back. Do NOT `dz safedel clean`.
- Remove the sandbox aggregator / `test_runs/` scratch dirs.
- Restore any `~/.safedel-trash` permission changes from section 1.1.
