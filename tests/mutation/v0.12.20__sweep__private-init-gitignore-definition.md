## What the code claims

`PRIVATE_GITIGNORE_SECTIONS` is the definition of what a correct private vault ignores;
`PARENT_GITIGNORE_SECTIONS` is the counterpart for the project that contains it.
`render_gitignore()` turns either into `.gitignore` text, `gitignore_patterns()` flattens
either into patterns in declaration order, and `PRIVATE_GITIGNORE` is the rendered vault
definition that `cmd_init` writes. The tests ask **git itself** -- `git check-ignore` in a
temporary repository -- whether the rendered text ignores what it should, rather than
asserting that a string contains a substring.

## Caveats

- A kill proves the suite noticed *this* change, not that it tests the right thing.
- **A clean sweep is evidence about the mutations tried, not proof of suite completeness.**
- The generator saw only the changed region. Nothing elsewhere in `private_init.py` was
  mutated, so this says nothing about the rest of the file -- including `cmd_status` and
  `cmd_init`, which units 2 and 3 of this slice will change and which will need their own run.
- One generator hypothesis (`m8`) was factually wrong about git's matching. Generator notes
  are prompts for triage, not findings.
